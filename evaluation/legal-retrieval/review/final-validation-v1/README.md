# KURE 확대 최종 검증 계획

모델 선정 후 고정한 새 평가다. KURE-v1 revision, 1024차원, 300자·중복 64자, 문서 입력·정제 원칙을 변경하지 않는다. 결과를 본 뒤 이 평가의 질문·정답·기준값을 조정하지 않는다. 기존 모델 비교 결과를 덮어쓰지 않는다.

| 항목 | 기존 모델 비교 | 확대 검증 |
| --- | ---: | ---: |
| 주 법령 | 20개 | 30개 |
| 원문 단위 | 5,486개 | 6,527개 |
| 300자 청크 | 8,497개 | 10,999개 |
| 질문 | 110개 | 270개 |
| 새 질문 | 없음 | 양성 120개·음성 40개 |
| 검색 실행 | 구성당 원본·정제 220개 | KURE 원본·정제 540개 |

행정절차법·행정심판법·행정소송법·국가공무원법·산업안전보건법·정보공개법·건축법·환경정책기본법·지방세기본법·주택법을 추가했다. 기존 법령·보충 근거·PDF 근거를 그대로 유지해 검색 방해 후보도 함께 늘린다. 새 법령의 공식 본문은 [출처 목록](source-inventory.json), 질문별 정답 근거는 [근거 검토 기록](gold-evidence.json)에 고정했다. 삭제 조문은 새 정답에 사용하지 않았다.

새 양성은 법령당 12개, 총 120개다. 단일 근거 100개에 두 조문을 함께 회수해야 하는 다중 근거 20개를 더했다. 새 음성은 외국 관할 법률 20개와 제공되지 않은 개인 사건의 실제 정보 20개다. 정제문에 법령 조문 번호를 추가하지 않는다. 음성은 원문을 그대로 사용해 정제가 외국 관할이나 사실 부재를 지우지 않게 한다.

기존 110개는 회귀 확인용이며 새 독립 증거로 세지 않는다. 새 질문 160개는 모두 별도 검증용으로 고정하고 기존 정답 조문과 겹치지 않음을 검사한다. 같은 새 조문을 단일·다중 질문에서 함께 사용하는 경우가 있어 120개가 완전히 독립인 표본이라는 뜻은 아니다. 새 질문과 정제본은 공식 근거를 본 어시스턴트가 작성했으므로 제삼자 블라인드 평가나 실제 사용자 질문 평가로 부르지 않는다. 법령도 의도적으로 고른 분야이며 무작위 법령 표본이 아니다.

## 결과를 보기 전에 고정한 판정

다음 네 조건을 모두 만족하면 이번 **검색 기준선 확대 검증 통과**로 표시한다.

1. 신규 정제 질문의 Recall@5 ≥ 75%.
2. 신규 정제 질문의 Complete@5 ≥ 60%.
3. 검색 후보가 늘어난 뒤 기존 검증용 정제 Recall@5가 75.52% 이상: 기존 80.52%에서 최대 5%p 하락 허용.
4. 신규 질문에서 정제 Recall@5가 원본보다 낮지 않을 것.

이는 이번 검증의 사전 공학적 목표이며 통계적 우월성이나 운영 SLA를 뜻하지 않는다. 법령별·단일/다중 근거별 결과와 실패 질문을 CSV에 남긴다. MRR은 상위 10개 기반 MRR@10으로 표시하고, 기존 전체 순위 MRR과 직접 비교하지 않는다. 원본·정제별 수용 기준값은 기존 개발용으로 정한 값을 그대로 쓰며 확대 평가에서 재교정하지 않는다. 음성 오수용률은 별도 진단으로 공개하며 생성 답변 안전성을 대신하지 않는다. 검증 통과와 관계없이 서비스 준비 상태는 `serviceReady=false`다.

## 실행 및 보관

입력과 해시는 [고정 manifest](../../data/final-validation-v1/manifest.json)에 있다. `test-final-validation.ps1`는 입력 해시·질문 중복·기존 질문 동일성·새 정답 누수·청크 범위·해시·정답 집합을 검사한다. 기존 입력은 재선정하지 않는다.

```powershell
$runner=Join-Path $PWD 'evaluation/legal-retrieval/scripts/run-kure-final-validation.ps1'
Start-Process powershell.exe -ArgumentList @('-NoExit','-NoProfile','-ExecutionPolicy','Bypass','-File',('"'+$runner+'"')) -WorkingDirectory $PWD.Path
```

별도 터미널 한 개에서 CPU 6개·메모리 8GB로 순차 실행한다. 문서 벡터는 기존 KURE 캐시에서 재사용하고 추가 2,502개 문서 입력만 새로 생성한다. 새 데이터·벡터·질문·결과는 이름이 분리된 Qdrant 확대 검증 컬렉션에 보관하며 기존 컬렉션을 삭제하지 않는다. 당시 실험 DB는 약 996MB, C드라이브 여유는 약 74GB로 보존하기로 했다.

결과는 `reports/final-validation-v1/kure-v1/`, 로그는 Git 제외된 `artifacts/logs/kure-final-validation-v1-*.log`에 남긴다. 완료·실패 시 KURE 컨테이너를 종료한다. 채팅 에이전트는 반복 폴링하지 않는다. 실패 시 캐시를 재사용할 수 있으며, 중지하려면 `artifacts/control/stop-kure-final-validation-v1.flag`를 생성한다. 결과의 커밋·푸시는 검증 결과를 확인한 뒤 수행한다.
