# 검색 방식별 단계 비교 계획

2026-10-20 사용자 지정 순서. 각 단계에서 바꾸는 요소를 분리해 질의 추가·단어 검색·결합의 효과를 비교한다. 1번은 완료된 결과를 재사용하며 2~4번은 실행 전 계획이다.

| 우선순위 | 실험 | 검색 입력과 방법 | 확인할 것 |
| ---: | --- | --- | --- |
| 1 | Legal Transformed + Dense | 법률 쟁점 변환문으로 KURE dense 검색 | 현재 기준선 |
| 2 | Original + Transformed Dense | 원본과 법률 쟁점 변환문을 각각 KURE 검색 후 RRF 결합 | Multi-Query 추가 효과 |
| 3 | Legal Transformed + BM25 | 법률 쟁점 변환문으로 BM25 단독 검색 | 단어 검색의 독립 성능과 dense 누락 보완 가능성 |
| 4 | Dense + BM25 + RRF | 같은 법률 쟁점 변환문의 dense와 BM25 결과 결합 | 하이브리드의 실제 개선 폭 |

2번의 transformed는 기존 의미 보존 정제가 아닌 법률 쟁점 변환문이다. 4번도 같은 변환문 하나를 두 검색기에 사용한다. 2번의 두 dense 질의와 BM25를 한꺼번에 묶는 추가 실험은 이번 네 단계에 포함하지 않는다. KURE-v2·재정렬·새 질문·LLM 변환 수정도 섞지 않는다.

## 공통 조건과 기준선

- KURE-v1 revision `8b418a58414668e75532ed045c22d9ca018ae2b2`, 1024차원.
- 후속 비교의 공통 청크는 500자·중복 64자. 원문 6,527개 단위, 청크 8,286개를 고정한다. 이는 이번 튜닝 비교를 위한 작업 기준이며 과거 300자 선정 기록이나 서비스 설정을 바꾸는 결정이 아니다.
- 고정 질문 100개: 코퍼스 내 36개, 추가 자료 필요 44개, 지원 범위 밖 15개, 사실 부족 5개. 질문·정답·원본·법률 쟁점 변환문을 변경하지 않는다.
- dense와 BM25의 문서 내용은 같은 제목+청크 본문이다. 조문·별표 등 `unit_id`별 최대 자식 청크 점수로 원문 단위 순위를 만든다.
- **Hit@5·Complete@5 공동 우선**, Recall@50·Hit@50·Complete@50은 후보 범위 진단, Recall@5·MRR@10·nDCG·지연·자원은 보조 지표다.

현재 1번의 코퍼스 내 36문항 기준선은 Hit@5 **20/36(55.56%)**, Complete@5 **4/36(11.11%)**, Recall@5 31.39%, Recall@50 56.57%, Hit@50 30/36, Complete@50 11/36이다. [500자 원자료](../../reports/legal-query-chunks-v1/kure-v1/char500/summary.csv)와 [후보 50개 평가](../../reports/recall50-v1/kure-v1/README.md)를 따른다.

## 후보 수와 RRF 비교 규칙

각 검색 경로는 상위 50개 원문 단위 후보를 조회한다. 중복 청크를 먼저 원문 단위로 묶고 한 경로에서 같은 원문이 여러 표를 얻지 않게 한다. 1·3번은 해당 순위의 상위 50개를 후보, 상위 5개를 최종 결과로 사용한다. 2·4번은 두 경로의 최대 100개 합집합을 RRF로 정렬한 뒤 상위 50개 후보와 최종 상위 5개를 평가한다.

RRF는 두 경로의 같은 가중치, 1부터 시작하는 순위에 `sum(1 / (60 + rank))`를 사용하도록 실행 전에 고정한다. 60은 이번 실험 상수이며 Qdrant의 서버 기본값을 뜻하지 않는다. 한 경로에 없는 원문은 그 경로에서 0점을 얻고, 동점은 고정된 unit_id 순서로 처리한다. 2번과 4번에 같은 결합 규칙을 적용해 질의 수 변화와 검색기 변화의 효과를 나누어 본다.

두 경로 실험은 최종 후보 50개는 같아도 조회 경로와 결합 전 최대 후보 수가 더 많다. 따라서 계산 예산까지 같다고 표현하지 않는다. 경로별 조회 수·중복 수·합집합 수·결합 후 정답 포함·최종 정답을 함께 기록하며 필요 시 dense 단독 후보 100개를 보조 확인해 후보 예산 증가의 효과를 구분한다.

## BM25 실행 전 고정할 계약

한국어 토큰화·정규화와 BM25의 k1·b·IDF 통계를 기록한 뒤 색인과 평가를 실행한다. 문서와 질의에 같은 토큰화 규칙을 적용하고, 조사·띄어쓰기·복합 법률 용어·가지 조문번호가 잘못 합쳐지거나 사라지지 않는지 먼저 확인한다. 공통 청크를 재파싱하거나 추가 법령을 수집하지 않는다.

3번은 BM25 단독으로 실행한다. 결과를 보고 문항별로 유리한 토큰화나 변환을 골라 적용하지 않는다. 일치하는 토큰이 없어 점수가 0인 문서는 임의로 50개를 채우지 않는다. 실제 반환 개수와 빈 결과를 기록한다. 4번은 3번과 같은 BM25 색인·질의·설정을 재사용한다. 별도 학습 sparse 모델은 이번 BM25 비교에 추가하지 않는다.

## 분석과 해석

1↔2로 원본 질의를 추가한 효과, 1↔3으로 단독 검색기의 차이, 1↔4 및 3↔4로 결합 효과를 본다. 2↔4는 같은 두 경로·동일 RRF 조건에서 두 번째 경로를 원본 dense에서 BM25로 바꾼 효과를 비교한다. 단계별 Hit@5·Complete@5 문항 수와 개선·악화 질문 ID를 남기고, dense가 누락한 정답을 BM25가 후보에 추가했는지도 확인한다.

현재 dense의 코사인 임계값을 BM25 점수나 RRF 점수에 그대로 사용하지 않는다. 후보 생성·순위 결합 효과를 우선 측정하고, 다른 64문항은 결과 유무·구성 점수·출처 부족 사례를 따로 보고한다. 점수만으로 실제 LLM의 범위 판단이나 답변 정오를 측정했다고 주장하지 않는다.

이 데이터는 이미 전략과 임계값을 탐색한 튜닝셋이다. 네 단계 비교도 새 독립 held-out 결과가 아니다. 두 우선 지표가 상충하면 임의 종합 점수로 한쪽을 우승 처리하지 않는다. 효과를 확인한 뒤 새 질문과 정답을 고정해 별도 최종 검증한다.

실험 실행 시 기존 문서·질문·벡터·결과는 보존하고 별도 컬렉션과 보고서에 저장한다. 무거운 작업은 별도 터미널에서 순차 실행하며, 모델 추론이 필요한 작업을 동시에 실행하지 않는다. 이번 변경은 계획 기록이며 BM25 다운로드·색인·검색, Multi-Query·RRF 실행, 서비스 설정 변경은 수행하지 않았다.
