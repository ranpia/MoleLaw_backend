# KURE-v1 법령 검색 평가

## 300·500·700문자 정제 질문 비교

같은 정제 질문 110개와 기존 문서 벡터로 세 청크 크기의 평가를 완료했다. 각 크기는 Qdrant 컬렉션을 분리했고 원본·정제 질문의 전수·근사 검색과 반복 검색 시간도 측정했다.

| 문자 | 개발용 Recall@5 원본 → 정제 | 검증용 Recall@5 원본 → 정제 | 검증용 정제 MRR |
| ---: | ---: | ---: | ---: |
| 300 | 57.11% → 75.17% | 71.71% → 80.52% | 0.7346 |
| 500 | 57.28% → 73.50% | 73.81% → 81.12% | 0.7655 |
| 700 | 58.39% → 73.50% | 76.48% → 81.12% | 0.7699 |

개발용 Recall@5를 우선하면 정제 입력의 KURE에서는 300문자가 가장 높다. 검증용 Recall@5는 500·700문자가 같고 첫 정답 순위의 MRR은 700문자가 높다. 작은 표본의 지표 차이를 구별해서 읽으며 검증용 결과로 질문을 다시 조정하지 않는다. [청크·정제·Qdrant 통합 비교](../chunk-experiments/comparison.md)에서 다른 모델과 함께 볼 수 있다.

## 2026-10-19 정제 질문과 Qdrant 재평가

700문자 문서 벡터 6,031개를 재사용해 원본·정제 질문을 비교하고 Qdrant 전수·근사 검색을 평가했다. 정제본은 Gemma·BGE-M3와 같은 고정 질문 110개이며 새로 만들거나 결과에 맞춰 고치지 않았다.

| 분할 | 원본 Recall@5 | 정제 Recall@5 | 원본 MRR | 정제 MRR |
| --- | ---: | ---: | ---: | ---: |
| 개발용 양성 30개 | 58.39% | 73.50% | 0.6153 | 0.7213 |
| 검증용 양성 70개 | 76.48% | 81.12% | 0.6526 | 0.7699 |

정제 후 검증용 Recall@5는 BGE-M3 80.95%보다 약 0.17%p 높지만, MRR은 BGE-M3 0.8036보다 낮다. 정제 입력에 따라 모델 비교 결과가 달라졌다는 탐색 결과로 본다. 대화형 어시스턴트가 작성한 정제본이며 블라인드 검증이나 자동 정제 API 성능 검증은 아니다.

[세 모델 정제 전후 비교](../query-rewrite-v1/comparison.md), [Qdrant 검색 품질·반복 시간](../qdrant-lab/benchmark/comparison.md), [KURE 컬렉션 검증](../qdrant-lab/kure-v1-verification.json)에서 상세 결과를 확인할 수 있다. 위 표의 MRR은 전체 순위 기준이며 Qdrant 보고서의 MRR@10과 구별한다.

## 원본 질문 청크 비교 기록

고려대 [공식 KURE-v1](https://huggingface.co/nlpai-lab/KURE-v1), revision `8b418a58414668e75532ed045c22d9ca018ae2b2`, 기본 출력 1,024차원이다. 동일 원문 5,486개 단위·질문 110개·정답·분할을 사용한다. 2026-10-16 500 / 300문자를 완료하고 일시 중단한 뒤 사용자 재개 지시로 700문자까지 완료했다. 재개 시 같은 이미지·revision·라이브러리 버전을 확인했다. 모델 볼륨·벡터 캐시·완료 결과를 보존한다.

| 최대 문자 | Recall@5 | Recall@10 | MRR | Hit@5 | Complete@5 | Precision@5 | nDCG@5 | nDCG@10 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 300 | 57.11% | 72.22% | 0.6160 | 66.67% | 43.33% | 18.67% | 0.5316 | 0.5856 |
| 500 | 57.28% | 73.33% | 0.6245 | 73.33% | 43.33% | 18.67% | 0.537 | 0.5987 |
| 700 | 58.39% | 73.33% | 0.6153 | 73.33% | 43.33% | 19.33% | 0.5438 | 0.6021 |

KURE 내 1차 지표 Recall@5는 700문자가 가장 높고, MRR은 500문자가 가장 높다. 500문자 구성에서 Recall@5는 BGE-M3 64.06%·Gemma 62.28%보다 낮지만 MRR은 두 모델보다 높다. 첫 정답의 순위와 여러 정답 조문의 회수율은 구분해서 해석한다. 개발용 양성 30개·음성 5개의 작은 평가이며 한국어 추가 학습의 일반적인 우열을 뜻하지 않는다.

Qwen3 추가 전 세 모델·세 청크의 원본 질문 9개 구성에서는 development Recall@5 최대값이 BGE-M3 700문자 65.72%, Gemma 700문자 64.22%, KURE 700문자 58.39%다. MRR 최대값은 KURE 500문자 0.6245다. 미리 정한 Recall@5 기준의 우선 후보와 첫 정답 순위가 중요한 경우의 보조 후보를 구분한다. 이미 공개된 held-out으로 반복 선택하지 않으며 최종 검증이 필요하면 새 독립 질문셋을 마련한다.

CPU 6 threads / batch 16 / 메모리 8GiB / GPU 없음 조건에서 순차 실행한다. 모델은 Sentence Transformers/PyTorch float32이며 CLS pooling과 정규화를 적용한다. 공식 모델을 독립적으로 불러온 한국어 입력 4개와 어댑터 출력의 최대 차이는 약 0.00000003이었다. [환경·이미지·전체 패키지 및 검증 기록](environment.json)을 보존했다.

신규 문서는 길이별로 묶어 PyTorch 패딩 비용을 줄이며 입력 내용과 배치 크기는 바꾸지 않는다. 첫 500문자 실행의 정상 벡터 176개를 재사용했고 이후 실행은 기존 KURE 입력만 전용 캐시에서 재사용한다. BGE-M3 벡터를 섞지 않는다. 런타임·정밀도가 기존 Ollama BF16/F16과 다르므로 warm 질문 지연을 순수 모델 속도로 비교하지 않으며 캐시가 있는 색인 시간도 최초 전체 색인 성능이 아니다.

각 완료된 청크 폴더에 summary.json·summary.csv·queries.csv·top10.csv를 저장한다. [공통 비교표](../comparison.md)는 입력 identity·해시·완료 파일 검증을 통과한 구성만 포함한다. 음성 수용률은 검색 점수 분류이며 생성 답변 거절 성능이 아니다. 이 초기 원본 보고서 이후 Qdrant 전수·근사 검색을 검증해 통합 비교에 반영했다. 서비스 RAG 답변 생성은 평가하지 않았다.

표의 값은 개발용 양성 30개 기준이다. Recall은 필요한 근거 중 찾은 비율, Hit는 하나 이상 찾은 질문의 비율, Complete는 전부 찾은 질문의 비율이다. Precision은 가져온 5개 중 정답 비율이며 MRR은 첫 정답의 위치, nDCG는 여러 정답의 배치를 본다. 모두 높을수록 좋지만 정답 확률은 아니다. [숫자 예시와 쉬운 설명](../similarity-and-metrics.md), [모델·분할별 통합 비교](../comparison.md)를 함께 참고한다.
