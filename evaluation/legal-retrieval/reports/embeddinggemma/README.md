# EmbeddingGemma 768차원 실제 법령 기준선

## 300·500·700문자 정제 질문 비교

같은 정제 질문과 기존 문서 벡터로 평가했다. 모델·청크·질문 정제의 전체 지표와 Qdrant 결과는 [통합 비교](../chunk-experiments/comparison.md)를 참고한다.

| 문자 | 개발용 Recall@5 원본 → 정제 | 검증용 Recall@5 원본 → 정제 | 검증용 정제 MRR |
| ---: | ---: | ---: | ---: |
| 300 | 61.28% → 72.00% | 74.69% → 77.90% | 0.7820 |
| 500 | 62.28% → 72.00% | 79.93% → 80.81% | 0.8136 |
| 700 | 64.22% → 72.00% | 78.14% → 78.43% | 0.7744 |

개발용 정제 Recall@5는 세 크기가 모두 72%로 같았다. 검증용 Recall@5와 MRR은 500문자가 높지만 검증용을 반복 선택 기준으로 쓰지 않는다. 질문별 개선·악화와 근거 전체 회수율도 함께 확인한다.

## 2026-10-16 재검토

- [공식 모델 카드](https://huggingface.co/google/embeddinggemma-300m)의 검색 입력 계약과 대조했다. 문서는 `title: {title} | text: {text}`, 질문은 `task: search result | query: {text}`를 사용한다. 기본 출력 768차원이며 이번 실험에서는 차원을 줄이지 않았다.
- 모델 digest·입력 형식·차원별 캐시 분리와 원문/질문 해시를 확인했다. 동일 digest의 기존 500문자 문서 벡터 6,634개를 재사용해 새 문서 벡터 생성 없이 질문 110개를 재평가했다.
- 보존된 기준선과 질문별 첫 정답 순위·MRR·Recall@5/10·1위 유사도, 분할별 적중률·수용률·임계값을 대조했다. 허용 오차 0.000001 내에서 일치했다. 시간 지표는 재실행 측정값이므로 일치 대상으로 삼지 않았다.
- 강화된 검증기와 비교표 생성기로 정답 세 표현, 원문·질문·정답·분할 identity, 결과 행과 split을 확인했다. 기존 기준선을 폐기하거나 전부 재임베딩할 이유는 발견하지 않았다.

아래 표와 루트 `summary.json`은 최초 500문자 기준선 기록이다. 재실행 및 청크별 결과는 `char<크기>-overlap64-article-v1/` 폴더에 별도로 보존한다. 모델·청크 비교는 [공통 비교표](../comparison.md)를 사용한다.

## 300 / 500 / 700문자 비교

2026-10-16 청크 비교를 완료했다. 동일 원문·질문·분할과 CPU 6 threads / batch 16 조건이다.

| 최대 문자 | Recall@5 | Recall@10 | MRR | Hit@5 | Complete@5 | Precision@5 | nDCG@5 | nDCG@10 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 300 | 61.28% | 70.72% | 0.5815 | 73.33% | 46.67% | 20% | 0.5301 | 0.5675 |
| 500 | 62.28% | 71.00% | 0.5854 | 73.33% | 50% | 20% | 0.5357 | 0.5719 |
| 700 | 64.22% | 71.00% | 0.6065 | 76.67% | 50% | 21.33% | 0.5543 | 0.5821 |

Gemma 내에서는 미리 정한 1차 지표 Recall@5와 보조 MRR 모두 700문자가 가장 높아 우선 후보로 둔다. 개발용 양성 30개의 결과이며 한국어 법령 전체에 대한 우열을 확정하지 않는다. BGE-M3 700문자와 development Recall@5 차이도 1.5%p에 불과하므로 한국어 추가 학습 후보까지 같은 기준으로 비교한다. 기존 공개 held-out을 반복적인 최적화 기준으로 사용하지 않는다.

## 최초 500문자 기준선

실행일: 2026-10-15. 공식 법령 본문과 필요한 보충 근거 6,634개 청크를 모두 벡터화하고 질문 110개를 실행했다.

| 지표 | 개발용 양성 30개 | held-out 양성 70개 |
| --- | ---: | ---: |
| 1위 적중률 | 43.33% | 70.0% |
| Recall@5 | 62.28% | 79.93% |
| Recall@10 | 71.00% | 84.60% |
| MRR | 0.5854 | 0.7861 |
| 질문 임베딩 평균 지연 | 41.88ms | 43.93ms |

범위 밖 질문은 개발용 5개 / held-out 5개로 별도 평가했다. 개발용 점수로 고정한 임계값은 약 0.49478이다. held-out 범위 밖 질문 5개 중 3개가 이 임계값 이상이었다. 이 기준선에서 유사도 임계값만으로 범위 밖 질문을 구분하는 성능은 충분하지 않았다. 실제 AI 답변 거절률을 측정한 것은 아니다.

코퍼스 범위·청킹·조문별 순위·라벨 계약은 ../../README.md를 따른다. 지표는 이 고정 평가셋에 대한 결과이며 한국어 법률 검색 전반의 정확도를 뜻하지 않는다. 다음 모델은 같은 질문·청크로 비교한다.

모델은 embeddinggemma:latest 768차원, CPU 6 threads / GPU 0이다. digest·Ollama 버전·코퍼스와 질문의 SHA256 및 전체 요약은 summary.json에 보존했다. 캐시 1,360개를 재사용하고 나머지 5,274개를 생성했으므로 보고서의 indexingWallMsThisRun을 전체 최초 색인 시간으로 해석하지 않는다.

표의 값은 개발용 양성 30개 기준이다. Recall은 필요한 근거 중 찾은 비율, Hit는 하나 이상 찾은 질문의 비율, Complete는 전부 찾은 질문의 비율이다. Precision은 가져온 5개 중 정답 비율이며 MRR은 첫 정답의 위치, nDCG는 여러 정답의 배치를 본다. 모두 높을수록 좋지만 정답 확률은 아니다. [숫자 예시와 쉬운 설명](../similarity-and-metrics.md), [모델·분할별 통합 비교](../comparison.md)를 함께 참고한다.
