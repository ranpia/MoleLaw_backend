# 현재 서비스 리랭커 전후 결과

2026-10-31, 기존 `experiment/legal-embedding-evaluation` 브랜치에서 36문항을 모두 완료했다. **Hit@5와 순위 지표는 개선됐지만 Complete@5는 그대로였다.** 필요한 근거를 모두 상위 5개에 넣는 효과까지 개선됐다고 해석하지 않는다.

## 조건

KURE-v1·500자·중복 64자·기존 법률 쟁점 변환 질의를 사용했다. 각 질문의 dense 상위 50개를 고정하고, 현재 실행 중인 `BAAI/bge-reranker-v2-m3`의 revision `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`로 순서만 바꿨다. 서비스와 동일한 제목·대표 청크 입력, CPU float32·배치 2·최대 1024토큰 설정이다. 모델·서비스 설정·코퍼스·정답·질의·벡터는 변경하지 않았다.

## 시간과 확인 범위

리랭커 HTTP 호출 시간은 평균 **33.09초**, p50 **30.97초**, p95 **66.12초**, 최대 **87.73초**였다. 36개 중 1개 응답은 사전 smoke 캐시를 재사용했고 해당 최초 측정 시간을 집계했다. 나머지 35개는 이번 전체 실행에서 추론했다.

현재 Spring 리랭커 읽기 타임아웃은 120초로 관찰했다. 모든 측정값은 그보다 짧았지만, 이번 실험은 dense 검색 시간·최종 생성·동시 사용자 부하를 포함하지 않는다. 전체 서비스 SLA나 답변 품질 합격으로 해석하지 않는다. 오프라인 실험 HTTP 제한은 별도로 300초다.

후보 50개에 정답이 하나라도 있는 질문은 30/36, 모든 정답이 있는 질문은 11/36이었다. 재정렬은 후보 밖 근거를 새로 가져오지 못한다. Complete@5를 개선하려면 이번 회귀 문항의 대표 청크·정답 범위를 검토하고, 후보 회수 단계와 재정렬 단계를 구분해서 실험해야 한다.

이 질문셋은 이미 탐색한 작은 튜닝 표본이다. 대체 정답 누락 가능성을 유지하며 새 독립 검증으로 해석하지 않는다. 현재 서비스 설정은 그대로 두었다.
