# 비교 조건 고정 기록

2026-10-31, `experiment/legal-embedding-evaluation`의 기존 실험 워크트리에서 진행한다.

## 비교 질문

현재 서비스의 BGE cross-encoder가 동일한 KURE dense 후보 50개에서 필요한 법령 근거를 상위 5개에 더 잘 배치하는가?

## 통제

- 현재 실제 실행 중인 리랭커 `/api/rerank`를 호출한다. 다른 모델·리비전으로 대체하지 않는다.
- 모델은 `BAAI/bge-reranker-v2-m3`, revision `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`다. CPU float32·배치 2·1024토큰 거절 정책을 유지한다.
- KURE-v1 500자·중복 64자, 법률 쟁점 변환 질의 36개와 기존 정답을 사용한다.
- 기존 dense 상위 50개를 원문 단위로 중복 제거한 순위·Cosine 점수 그대로 재확인했다. 각 원문의 대표 청크를 고정했다.
- 입력은 서비스와 같은 `제목 + 줄바꿈 + 대표 검색 청크`다. 리랭커가 볼 수 있는 정보는 질의와 후보 ID·문서 텍스트뿐이다.
- 원본 질문·질의 변환·정답·코퍼스·임베딩은 변경하지 않는다. Qdrant 쓰기·별칭 변경·재색인은 실행하지 않는다.
- 원시 cross-encoder 점수와 Cosine 점수를 섞지 않고 정렬 결과만 비교한다. 임계값 필터를 넣지 않는다. 동점은 dense 순위를 유지한다.
- 실패 문항을 제외하거나 dense fallback으로 채우지 않는다. 36개 미완료 실행은 최종 결과가 아니다.

## 사전 확인

고정 후보 파일은 질문 36개·후보 1,800개다. 재계산 기준선은 Hit@5 **20/36**, Complete@5 **4/36**, Recall@50 **56.5741%**로 과거 결과와 일치했다.

후보 50개 내에 정답이 하나라도 있는 질문은 30/36, 모든 정답이 있는 질문은 11/36이다. 동일 후보 재정렬의 Hit@5·Complete@5 이론 상한은 각각 30/36·11/36이며, Recall@50은 전후 같아야 한다.

실제 첫 50개 후보 smoke는 약 36.7초였다. 품질 평가는 현재 서버의 동일 추론 설정으로 실행하지만 오프라인 HTTP 제한은 300초다. 따라서 Spring의 서비스 요청 시간 제한·수용량을 통과했다는 결과로 해석하지 않는다. 처리 시간은 HTTP 대기·네트워크를 포함하며 dense 검색 시간은 이번 비교에서 재측정하지 않는다.

현재 백엔드의 `APP_LAW_RERANKER_READ_TIMEOUT_MILLIS` 환경변수는 **120000**으로 확인했다. 모델·리비전·활성화 여부와 함께 `data/c500-legal_transformed/spring-client.json`에 별도 보존한다. 오프라인 비교의 300초 제한과 이 서비스 설정은 구분한다.

## 검증과 한계

순수 계약 테스트는 모델·리비전 불일치, 결과 누락·중복·미지 ID, NaN, 문자열 점수, 안정적인 동점 처리, dense 점수 보존과 MRR·Recall 계산을 확인한다. 실험은 요청과 런타임 해시별 응답 캐시를 사용한다.

보고서는 Hit@5·Complete@5를 공동 우선으로 하고 Recall@5·nDCG·MRR과 질문별 상승/하락을 함께 보여준다. 이미 탐색한 작은 질문셋이므로 통계적 일반화·새 독립 검증·LLM 답변 품질·서비스 적용 확정으로 해석하지 않는다. 변경하지 않은 질문·정답의 대체 근거 누락 가능성도 유지한다.
