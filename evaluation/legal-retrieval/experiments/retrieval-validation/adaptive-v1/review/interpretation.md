# 반복 검색 비교 결과

현재 BGE 리랭커를 유지한 36문항 실험에서 **추가 검색은 최초 검색의 후보 회수 부족을 보완했다.** 후보 15개 안에서 정답 근거를 하나 이상 확보한 문항은 19개에서 26개로, 정답 근거를 모두 확보한 문항은 5개에서 8개로 늘었다. 이는 최종 답변의 정답률이 아닌 법령 근거 회수 결과다.

실행은 [full-serviceids-20261031](../reports/full-serviceids-20261031/README.md)이다. 같은 실행의 최초 후보와 종료 후보를 비교했으며 질문·정답·코퍼스·임베딩·리랭커는 고정했다. 초기 질문 분석의 무작위 차이가 두 조건의 차이가 되지 않도록 공통 최초 검색 결과를 사용했다. [세부 계약과 범위](protocol.md)를 함께 확인한다.

## 전체 36문항의 후보 비교

질문 분석 실패 5문항도 분모에 포함하고, 최초 후보가 없는 문항에는 양쪽 모두 0점을 부여했다.

| 지표 | 최초 검색 배치 후 | 반복 허용 종료 시 | 변화 |
| --- | ---: | ---: | ---: |
| Hit@15: 정답 근거 하나 이상 | 19/36, 52.78% | 26/36, 72.22% | +19.44%p |
| Complete@15: 정답 근거 모두 | 5/36, 13.89% | 8/36, 22.22% | +8.33%p |
| Recall@15: 질문별 정답 근거 회수율 평균 | 32.04% | 45.93% | +13.89%p |
| Hit@5 | 27.78% | 50.00% | +22.22%p |
| Complete@5 | 5.56% | 13.89% | +8.33%p |
| Recall@5 | 14.58% | 28.70% | +14.12%p |

최초 후보를 확보한 같은 31문항만 진단하면 Hit@15는 61.29%→83.87%, Complete@15는 16.13%→25.81%, Recall@15는 37.20%→53.33%다. 이 조건부 수치로 전체 성능을 대체하지 않는다.

## 어디서 개선됐나

실제 추가 검색을 실행한 문항은 **8/36개**였다. 나머지 문항의 두 후보 집합은 추가 검색 효과를 받지 않는다.

- Hit@15 개선 7문항, 악화 0문항.
- Complete@15 개선 3문항, 악화 0문항.
- 반복한 8문항 모두 종료 후보에 **최초 검색 배치의 dense 후보 집합 밖에 있던 정답**이 포함됐다. 초기 질의가 여러 개면 각 질의의 최대 50개 후보를 합친 집합을 기준으로 검사했다.
- 중간 판단 후보에 나타났다가 종료 후보에서 사라진 정답은 이번 실행에서 없었다.
- 검색 질의는 총 82회: 최초 배치 40회, 추가 검색 42회. 이 중 조문 지정 조회는 18회였다. 한 문항의 최대 검색 횟수는 13회였다.

따라서 이번 개선에는 최초 후보 안의 순서 변경뿐 아니라 **검색어 수정과 조문 지정으로 새 근거를 회수하는 효과**가 있다. 최초 후보 50개를 고정했던 이전 리랭커 전후 실험에서는 측정할 수 없던 부분이다. 다만 이전 실험의 단일 변환 질의와 이번 실제 질문 분석기가 만든 초기 질의는 다르므로 두 실험의 점수를 직접 빼서 요인별 기여도를 계산하지 않는다.

| 문항 | 질문 요약 | 최초 후보의 정답 수 | 종료 후보의 정답 수 | 근거 수집 종료 |
| --- | --- | ---: | ---: | --- |
| ind-004 | 보증금에서 청소비·도배비 공제 | 0/3 | 1/3 | 근거 부족 실패 |
| ind-005 | 차용증 없이 송금·카톡으로 빌려준 돈 회수 | 1/3 | 2/3 | 일부 근거 안내 |
| ind-006 | 개인 간 중고 노트북 하자·환불 | 0/3 | 1/3 | 일부 근거 안내 |
| ind-010 | 배달 음식 이물질과 병원비 | 0/3 | 3/3 | ANSWER_READY, 최종 선택에는 2/3 포함 |
| ind-018 | 근로자 동의 없는 손해액 임금 공제 | 0/2 | 1/2 | 일부 근거 안내 |
| ind-028 | 학교에서 다친 아이의 치료비 | 0/3 | 3/3 | ANSWER_READY |
| ind-034 | 형제가 혼자 인출한 상속 예금 | 0/3 | 3/3 | ANSWER_READY |
| ind-037 | 치료 중 교통사고 합의 | 0/4 | 2/4 | 일부 근거 안내 |

반복만이 현재 흐름의 차이는 아니다. ind-032의 이혼·양육·재산 문제는 최초 배치의 질의 4개만으로 정답 3개를 모두 확보했다. 최초 쟁점별 다중 검색과 최대 15개 후보 사용도 기존 단일 질의·top5 평가와의 차이다.

## 후보 회수와 실제 선택은 다르다

근거 수집이 정상 반환된 문항은 30개였다. 그중 `ANSWER_READY` 12개, `ANSWER_PARTIAL` 18개다. 답변 생성·인용 검증·채팅방 저장은 실행하지 않았다.

실패는 질문 분석 계약/출처 검증 5개(ind-002, 014, 019, 022, 059), 추가 행동을 모두 사용한 뒤 근거 부족 1개(ind-004)였다. 이 실행에서 외부 법령 수집 요청에 따른 중단은 없었다.

실패한 실행의 마지막 후보는 진단 자료일 뿐 사용자에게 전달된 근거가 아니다. 성공적으로 선택한 근거만 평가하고 실패 문항을 0점 처리하면 정답 하나 이상은 **25/36, 69.44%**, 전체 정답 확보는 **7/36, 19.44%**, 평균 회수율은 **44.07%**였다. 이 수치 역시 답변 정답률은 아니다.

ind-010은 마지막 후보에는 정답 3개가 있었지만 최종 선택에는 2개만 포함됐다. `ANSWER_READY`가 고정 정답 목록의 전체 충족을 보장하지는 않는다. 후보 회수, 읽기·선택, 최종 답변 평가는 나눠 봐야 한다.

## 처리 시간

최초 후보 확보에 성공한 같은 31문항의 평균은 최초 후보 확보 **34.49초**, 전체 근거 수집 **73.92초**였다. 전체 36문항 평균 근거 수집 시간은 64.75초, 최장 문항은 ind-004의 331.71초였다. 전체 본 실행은 약 39분이 걸렸다.

최초 시간에는 근거 읽기·최초 충분성 판단이 포함되지 않는다. 따라서 34.49→73.92초 차이를 추가 검색만의 순수 지연으로 해석하지 않는다. 실제 서비스 답변 생성까지의 지연이나 동시 부하 성능도 측정하지 않았다. 로컬 CPU float32, BGE 배치 2, 최대 pair 1,024 tokens의 관측값이다.

## 해석과 검증

이번 36문항에서는 반복 검색이 체감 품질을 높일 수 있는 기여가 확인됐다. 특히 최초 후보 밖의 조문을 추가로 찾았다. 다만 필요한 근거 전부를 확보하는 수준은 여전히 낮고, 검색 이전 계약 검증과 읽기·선택 단계에도 실패·누락이 남는다.

이 결과는 이미 탐색에 사용한 소규모 질문셋의 한 번의 실제 LLM 실행이다. 새로운 홀드아웃·반복 실행의 통계 검증은 아니며, 정답 목록 밖의 타당한 조문은 인정하지 않는다. 고정 실험 코퍼스와 원문 복원 어댑터를 사용했고 외부 법령 추가 수집을 제외했다. 최초 법령 검색의 결과이며 후속 판례 검색이나 실제 최종 답변 정확도로 일반화하지 않는다.

실제로 통과한 검증:

- 36개 원본 추적과 모든 라운드의 초기/종료 후보·예산·근거 ID·리랭킹 계약 검사.
- 정답 집합 교집합을 이용한 독립 재계산: 최초 19 hit/5 complete, 종료 26 hit/8 complete, 최종 선택 25 hit/7 complete 일치.
- 최초 dense 후보 밖의 정답 진단을 원본 추적에서 독립 재검사.
- 정상 회수율 계산, 실패 실행 0점 처리, 미지 근거 선택 및 종료 풀 불일치 거부 계약 테스트.
- 현재 소스·프롬프트 236개, 빌드 관련 6개, 고정 실험 입력 5개, 과거 기준선 3개의 해시 보존.
- Qdrant 정확한 포인트 수 8,286개와 설정·소유권·코퍼스 식별자 유지, 모델 컨테이너·이미지·KURE 런타임 유지.
- Java 컴파일, PowerShell 구문·UTF-8 BOM, 문서 링크 및 Git whitespace 확인.

집계 원본은 [summary.csv](../reports/full-serviceids-20261031/summary.csv), [queries.csv](../reports/full-serviceids-20261031/queries.csv), [paired.json](../reports/full-serviceids-20261031/paired.json)이다. 독립 계산은 [independent-recalculation.json](../reports/full-serviceids-20261031/independent-recalculation.json), 보존 검증은 [validation.json](../reports/full-serviceids-20261031/validation.json)에 있다. 준비·중단 실행은 최종 집계에 포함하지 않았다.
