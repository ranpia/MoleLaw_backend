# 비교 계약

## 질문과 고정 조건

서비스가 단일 검색 평가보다 잘 동작해 보이는 이유 중 **추가 검색과 근거 누적의 기여**를 확인한다. 리랭커를 켠 상태로 두며, 질문과 정답은 이전 탐색 실험에서 이미 사용한 in-corpus 36문항을 그대로 사용한다. 새로운 독립 평가셋은 아니다.

대상은 최초 질문의 Qdrant 법령 근거 수집 흐름이다. 후속 판례 검색·판례 본문 읽기·판례 관련성 판단은 별도 흐름이므로 이 결과에 포함하지 않는다.

문항마다 실행은 한 번이다. 동일 실행의 최초 검색 배치가 끝난 지점을 단발 검색 조건으로 취하고, 그 뒤 실제 서비스의 판단에 따라 진행한 종료 지점을 반복 허용 조건으로 취한다. 따라서 초기 LLM 질문 분석의 무작위 차이를 비교 차이로 오인하지 않는다. 단발 조건도 초기 쟁점별 여러 질의를 허용하며, **하나의 고정 질의 실험과는 다르다**. 단발 종료 전용 프롬프트를 따로 적용하지 않는다.

고정 조건:

- 질문·정답: 이전 `reranker-v1/c500-legal_transformed/candidates.jsonl`의 `originalText`, `goldUnitIds`. 기존 변환 검색어는 재사용하지 않고 실제 질문 분석기가 질의를 만든다. 정답은 모델 입력에서 제외한다.
- 문서: `molelaw_legal_chunks_kure_v1_c500_431ce0e1_8b418a58`, 8,286개 청크. 코퍼스 SHA-256 `431CE0E1D41EE6894F21E8966E49396387147E788CC8DBF0DB8255990EA5353E`.
- 임베딩: KURE-v1 revision `8b418a58414668e75532ed045c22d9ca018ae2b2`, 1,024차원, 정규화된 CLS, CPU float32. 질의만 새로 임베딩하고 저장 벡터는 변경하지 않는다.
- 검색: 기존 실험 컬렉션에 exact cosine grouped 최대 top50, 원문 단위 중복 제거. 서비스의 `LawArticleQuery.paths`로 조문 지정 여부를 판단하며, 법령명·조문번호를 지정한 질의는 서비스처럼 해당 조문만 검색하고 일반 검색으로 대체하지 않는다. 이 경우 후보는 50개보다 적을 수 있다. 서비스의 `LawRerankerClient`로 `BAAI/bge-reranker-v2-m3` revision `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`를 호출해 최대 top15 반환. 입력은 제목과 대표 청크다.
- 질문 분석: `gpt-5.4-mini`, low, 4,096 completion tokens. 근거 읽기: `gpt-5.4-mini`, low, 4,096. 근거 판단: `gpt-5.4`, medium, 12,288. 운영 중 컨테이너의 명시 설정을 확인하고 서비스 기본 읽기 설정을 적용한다.
- 근거 입력 한도 8,000, 읽기 카탈로그 8,000, 본문 12,000, 통합 판단 32,000 tokens. 전체 수집 제한 15분, BGE 읽기 제한 120초.
- 실험용 OpenAI HTTP 읽기 제한은 120초이며 공급자 오류에 대한 자동 재시도는 하지 않는다. 서비스의 기본 공급자 재시도 설정과는 차이가 있어 일시적 공급자 오류가 발생하면 완료율을 더 보수적으로 측정할 수 있다. 서비스 코드에 있는 행동 계약 보정은 그대로 실행한다.
- `LegalEvidenceCollector`, `QuestionRetrievalPlanner`, `EvidenceDecisionPlanner`, `EvidenceReadPlanner`, RRF, 후보 균형·보존 로직과 중복 질의 방지는 복사한 현재 소스를 그대로 실행한다. 최초 검색 후 최대 네 번의 추가 행동을 허용한다.

## 어댑터와 실행 범위

서비스의 MySQL 색인·원문 저장소 대신 검증된 기존 실험 코퍼스를 읽는 어댑터를 사용한다. 청크 위치와 겹침을 검사해 온전한 조문을 복원하고, Qdrant 대표 청크의 단위 ID·제목·본문 포함 관계를 검사한다. 근거 읽기는 SQL 원문 재복원 대신 이 고정 본문을 제공한다. 검색과 누적에는 서비스 형식인 `MST:조문경로` ID를 쓰고, 보고서에서는 원래 정답 ID로 환산하되 `canonicalSourceId`/`canonicalUnitId`를 함께 보존한다. ID 변환은 일대일 대응을 검사한다. 별표·고시는 기존 실험의 특수 자료이므로 별도 가상 출처 ID를 사용한다. 수집 법령명은 기존 수집 매니페스트에서 제공한다.

서비스의 SQL 색인 공개·원문 복원 검증을 포함하는 `LawRagSearchToolService` 전체를 재현하는 실험은 아니다. 해당 저장소 경계를 고정 Qdrant 검색으로 바꾸되, 조문 지정 필터를 보존하며 리랭킹과 검색 조정은 현재 서비스 코드를 쓴다. 코퍼스에 과거 실험의 별표·고시가 포함되어 있어 현재 서비스의 본문 색인 범위와도 차이가 있다. 실제 서비스의 전체 답변 성능으로 일반화하지 않는다.

`fixed-index-only=true`를 적용해 외부 OpenLaw 조회·수집·ETL·인덱스 쓰기를 금지한다. 판단기가 `COLLECT_LAW`를 선택하면 서비스의 기존 고정 색인 모드대로 실패 종료한다. 이를 재검색으로 임의 변경하거나 성공으로 간주하지 않는다. 이 실험은 추가 수집의 효과를 측정하지 않는다. 시간 초과·형식 오류·근거 부족도 포함한 전체 문항을 보고하며 실패 문항을 제외해 점수를 높이지 않는다.

## 지표와 해석

주 비교는 동일 최대 15개 후보 풀의 최초 대비 종료 시 **Hit@15·Complete@15·Recall@15**다. 상위 5개 지표도 보조로 기록한다. 후보 정렬은 서비스의 쟁점 균형·누적 보존 로직을 거친 순서로, 단순 리랭커 점수 순서와 다를 수 있다.

`initialPool`은 최초 판단기에 전달한 후보, `lastPool`은 마지막 판단기에 전달한 후보다. 모든 반복 라운드와 실제 검색 질의·dense50·리랭킹 top15를 저장한다. 후보를 읽기 전에 기록하므로 판단 실패에도 후보 회수율 자체는 진단할 수 있다. **실패한 실행의 terminal 후보는 사용자에게 전달된 근거가 아니다.** 성공적으로 선택한 근거의 별도 집계에서는 실패 문항에 0점을 부여한다. `ANSWER_READY`와 `ANSWER_PARTIAL`도 구분한다.

추가로 개선/악화 문항 수, 최초·전체 검색 수, 재검색 수행 문항 수, 종료 행동, 최초 후보 확보 시간과 전체 처리 시간을 기록한다. 최초 시간에는 최초 충분성 판단이 포함되지 않으므로, 전체 시간과의 차이는 추가 검색만의 순수 지연이 아니다. 카탈로그 읽기와 근거 판단 시간도 포함한다. 최종 답변 생성·인용 검증·사용자 정답률은 측정하지 않는다. 선택 근거의 순서는 관련성 순위가 보장되지 않아 selected의 순위 지표는 참고값이며, 집합 회수율을 우선한다.

전체 36문항 지표와 최초 후보 확보에 성공한 동일 문항 집합의 지표를 함께 제공한다. 후자는 초기 분석 실패의 영향을 제외한 반복 검색 진단용이며 전체 성능으로 대체하지 않는다. 지연 비교도 최초 후보 확보 문항을 동일하게 맞춘 평균을 별도로 기록한다. 각 라운드에서 한 번이라도 나타난 정답과 종료 시 남은 정답을 비교해 후보 보존 손실도 기록한다.

한 번의 실제 LLM 실행으로 반복성·통계적 확실성을 증명하지 않는다. 정답 목록 밖의 타당한 조문은 자동 평가에서 인정되지 않는다. 새 홀드아웃·사람의 답변 검토가 필요한 한계를 유지한다.

## 검증과 보존

실행 전후 Qdrant 정확한 포인트 수와 설정·소유권·모델·코퍼스 식별자를 비교한다. 소스 복사본의 모든 파일 해시와 원본 HEAD를 보고서에 남긴다. 원본 작업 트리가 수정 중일 수 있으므로 HEAD만으로 현재 코드를 식별하지 않는다. 준비 실행과 본 실행의 소스·하네스 버전도 분리한다. 질문 결과·run manifest는 덮어쓰지 않는다.

재계산기는 질문/정답 동일성, 최초/마지막 라운드 풀 일치, 추가 행동 예산, 알려진 근거 ID, dense50/top15의 단위·본문·cosine 보존과 성공/실패 근거 계약을 검사한 뒤 CSV를 생성한다. 부분 실행은 명시적인 `-AllowPartial`에만 허용한다.
