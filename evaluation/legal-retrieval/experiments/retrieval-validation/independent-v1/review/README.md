# 독립 역할 분리 질문 검증 v1

2026-10-20 준비. 이전 평가의 공식 원문을 보며 질문을 작성한 한계를 보완한다. 모델·청킹·문서 색인·유사도 기준값은 바꾸지 않는다. 기존 평가와 다른 새 질문을 작성하고 정답을 별도 역할에서 확인한다.

## 역할과 열람 경계

1. 질문 작성: 대화 기록을 전달하지 않은 에이전트가 기존 질문·법령 원문·정답·검색 결과를 읽지 않고 100문항을 작성한다. 일반 국내 법률 60개, 전문 국내 법률 20개, 해외 관할 10개, 개인 사건 현황 5개, 핵심 사실 부족 5개를 작성 목표로 삼는다. 실제 코퍼스 포함 여부를 보고 질문을 바꾸지 않는다.
2. 질문 정제: 정답·원문·검색 결과를 읽지 않고 의미 보존 정제문을 작성한다. 법령명·조문·사실을 새로 주입하지 않는다. 원본과 정제본은 검색 전에 고정한다.
3. 정답 확인: 별도 에이전트가 고정 코퍼스와 공식 출처를 확인하고 질문을 실제 범위별로 분류한다. 목표 문항 비율에 맞추기 위해 정답이나 질문을 바꾸지 않는다.
4. 독립 검수: 또 다른 에이전트가 원문·분류·정답 집합의 누락과 모호함을 검토한다. 질문은 보존하고 정답 오류만 실행 전에 수정 내역을 남긴다.
5. 실행: 질문·정제·정답·검수 내역의 해시를 고정하고 별도 터미널에서 KURE를 순차 실행한다. 검색 결과를 보고 정답을 고치지 않는다.

## 고정 검색 조건

- KURE-v1 revision `8b418a58414668e75532ed045c22d9ca018ae2b2`, 1024차원, 300자·중복 64자, 원래 문서·질문 입력 형식.
- 기존 확대 코퍼스: 주 법령 30개와 보충 자료, 6,527개 원문 단위·10,999개 청크. 문서 벡터 재생성·법령 추가 수집은 하지 않는다.
- 기존 Qdrant 확대 문서 컬렉션을 읽고, 새 질문 벡터·결과는 별도 컬렉션에 저장한다. 전수 코사인 검색 후 조문별 최대 자식 점수로 상위 10개를 평가한다.
- 원본·정제 모두 평가한다. 기준값은 기존 개발용으로 고정한 원본 0.59257074600968018, 정제 0.59829341466087427을 유지한다.

## 집계와 해석

실제 정답 검토 후 `in_corpus`(현재 자료로 법적 근거 확보 가능), `missing_corpus`(필요 국내 법령·버전 누락), `unsupported`(해외 관할·개인 사건 조회), `needs_clarification`(핵심 사실 부족)으로 나눈다. 복합 질문에 필요한 근거 일부가 없으면 완전한 코퍼스 내 양성으로 계산하지 않는다.

코퍼스 내 질문에 Recall@5/10·Hit@5·Complete@5·Precision@5·nDCG·MRR@10을 집계하고, 다른 집단은 유사도 기준값 통과율을 집계한다. 범위 밖 질문의 기준값 통과를 실제 LLM 판단 실패나 생성 답변 오류라고 부르지 않는다. 코퍼스 내에도 고정 정답 외 합리적인 근거가 있을 수 있어 판정 집합의 한계를 남긴다.

이번 검증은 기존 선정의 독립성 보강을 위한 진단이다. 결과로 모델·질문·청킹·기준값을 재조정하거나 합격 기준을 사후 설정하지 않는다. 이전 원문 기반 질문셋보다 어려울 수 있으며 직접적인 성능 상승·하락으로 해석하지 않는다. 정답과 질문 역할은 분리했지만 같은 계열 LLM의 지식·편향이 겹칠 수 있고 사람·실사용자의 독립 평가를 대체하지 않는다.

## 실행과 후속 범위

CPU 6개·메모리 8GB, 추론 모델 하나로 실행하고 완료·실패 시 KURE를 중지한다. 문서 벡터는 재사용하고 새 질문 벡터만 생성한다. 로그는 Git 제외 경로 `artifacts/logs/`에 남긴다. 에이전트는 실행 후 반복 모니터링하지 않으며 사용자가 완료 출력을 전달하면 결과를 검토한다.

실제 서비스 LLM의 질문 정제·충분성 판단·자동 수집 후 재검색·최종 답변은 검증 범위가 아니다. 개발 계획은 dev 브랜치의 `docs/plans/adaptive-law-retrieval.md`에서 관리한다. 서비스 준비 상태는 `serviceReady=false`다.

## 실행 명령과 중지

정답 검수 완료 후 `prepare-independent-validation.ps1`가 질문·정제·정답·검수 당시 SHA와 원본 작성 SHA를 검사하고 입력을 고정한다. 작성 질문 100개는 그대로 보존하며 이전 평가와 문장이 정확히 같은 질문은 없다. 주제가 겹치지 않는다는 의미는 아니다.

```powershell
.\evaluation\legal-retrieval\scripts\prepare-independent-validation.ps1
.\evaluation\legal-retrieval\scripts\run-kure-independent-validation.ps1 -ValidateOnly
$runner=Join-Path $PWD 'evaluation/legal-retrieval/scripts/run-kure-independent-validation.ps1'
Start-Process powershell.exe -ArgumentList @('-NoExit','-NoProfile','-ExecutionPolicy','Bypass','-File',('"'+$runner+'"')) -WorkingDirectory $PWD.Path
```

입력 고정은 한 번만 실행하며 이미 manifest가 있으면 덮어쓰지 않는다. 모델 실행을 중단하려면 `artifacts/control/stop-kure-independent-validation-v1.flag`를 생성한다. 실행기는 다음 배치 또는 검색 전에 종료하고 캐시를 보존한다. 재개 시 사용자가 중지를 해제한 뒤 해당 파일을 제거해야 한다.

결과 경로는 `reports/independent-validation-v1/kure-v1/`이다. 보고서는 문항별 검색 지표와 상위 10개 조문 유사도를 남기며 새로운 질문 컬렉션은 `molelaw_independent_kure_v1_<questionsSHA8>`이다. 기존 문서 컬렉션은 수정하지 않는다.

## 실행 전 고정 완료

독립 검수에서 정답 관련 5문항을 수정했고 원본 질문과 정제문은 변경하지 않았다. 최종 분류는 코퍼스 내 36개, 추가 자료 필요 44개, 지원 범위 밖 15개, 사실 부족 5개다. 정제와 정답 100개 전수 검수 및 미해결 항목 0개를 확인했다. [고정 입력](../data/manifest.json), [검수와 변경 이력](audit.json)을 참고한다.

모델 실행 전 사전 검사에서 manifest의 분류 집계 메타데이터 오류를 수정했고 manifest에 이전 해시와 수정 사유를 기록했다. 질문·정제·정답·기준값은 변경하지 않았다. 고정 입력과 검토 파일 무결성 검사를 통과한 뒤 실행한다.
