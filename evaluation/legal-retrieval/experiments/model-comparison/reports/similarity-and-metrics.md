# 유사도와 평가지표를 읽는 방법

아래 수치 예시는 2026-10-16에 기존 세 모델의 저장 결과를 재집계한 설명용 기록이다. Qwen3를 포함한 최신 완료 조건의 지표는 [통합 비교](chunk-experiments/comparison.md), 원시 유사도 예시는 [CSV](similarity-examples.csv)를 기준으로 확인한다. 기존 원본 summary/queries/top10 파일은 보존한다.

## 유사도 점수 예시

700문자 / 중복 64문자 조건에서 검색 1위 조문의 코사인 유사도다. ✓는 고정 정답 조문에 해당함을 뜻한다. 질문 문장은 `similarity-examples.csv`와 원본 `top10.csv`에서 확인할 수 있다. 예시는 설명 목적으로 선택했으며 전체 표본의 성능을 대표하지 않는다.

| 질문 요약 | EmbeddingGemma 768차원 | BGE-M3 1024차원 | KURE-v1 1024차원 |
| --- | ---: | ---: | ---: |
| 계약 위반 시 손해배상 조건 | 0.5439 ✗ | 0.6754 ✗ | 0.6459 ✗ |
| 임대차 만료 후 묵시적 갱신 | 0.5579 ✗ | 0.5800 ✓ | 0.5906 ✓ |
| 장시간 근무 중 휴게시간 미제공 | 0.4455 ✗ | 0.5869 ✗ | 0.5602 ✓ |
| 개인정보 열람·삭제 요구 | 0.5768 ✓ | 0.7219 ✓ | 0.6804 ✓ |

휴게시간 질문에서 BGE-M3의 1위는 근로기준법 제50조(근로시간), KURE의 1위는 정답인 제54조(휴게)다. BGE의 점수가 더 높아도 정답 조문을 찾은 것은 KURE다. 코사인 유사도는 정답 확률이 아니며, 모델별 점수 분포가 다르므로 원시 점수로 모델 우열을 판단하지 않는다. 동일 모델 안에서도 주제·질문·청크 길이에 따라 분포가 달라질 수 있다. 임계값은 구성별 development에서 정하고 held-out에서는 고정한다.

조문 점수는 해당 조문의 자식 청크 중 최대 유사도다. 따라서 동일 질문이라도 모델마다 1위 조문이 달라질 수 있고, 위 표는 같은 문서 쌍의 임베딩 점수 비교가 아니다. 전체 순위와 정답 여부를 함께 확인해야 한다.

## 먼저 알아둘 용어

질문을 입력하면 모델은 관련 있어 보이는 조문부터 순서대로 보여 준다. 이 문서의 **정답**은 질문에 필요한 근거로 미리 지정한 조문이다. 답변 문장을 잘 썼다는 뜻은 아니다. **청크**는 긴 조문을 검색하기 좋게 나눈 작은 글 조각이고, 표의 300·500·700은 조각의 최대 문자 수다. **차원**은 글의 특징을 표현하는 숫자의 개수이며, 숫자가 많다고 검색이 반드시 좋아지지는 않는다.

**@5**는 검색 결과의 앞쪽 5개까지만 보겠다는 뜻이다. @10은 앞쪽 10개다. 같은 조문에서 나온 여러 조각은 하나의 조문으로 합쳐 계산한다.

**개발용(development)** 질문은 모델과 청크 크기를 비교하는 데 사용한 문제집이다. **검증용(held-out)** 질문은 따로 남겨 둔 확인용 문제집이다. 확인용 결과를 보고 계속 설정을 바꾸면 그 문제집에 맞춘 선택이 되므로, 이후 최종 확인에는 새 질문이 필요하다.

## 하나의 예시로 이해하기

어떤 질문에 필요한 정답 조문이 **A·B·C 세 개**라고 하자. 검색 결과가 **X → A → Y → B → Z**라면, 5개 중 정답은 A·B 두 개이고 C는 빠져 있다.

| 지표 | 이 예시의 값 | 쉽게 읽으면 |
| --- | ---: | --- |
| 1위 적중 | 0 | 첫 결과 X는 정답이 아니다. |
| Recall@5 | 2/3 = 66.67% | 필요한 근거 세 개 중 두 개를 찾았다. |
| Hit@5 | 1 | 정답을 하나 이상 찾는 데는 성공했다. |
| Complete@5 | 0 | 필요한 근거를 모두 찾지는 못했다. |
| Precision@5 | 2/5 = 40% | 가져온 조문 다섯 개 중 두 개가 정답이다. |
| 첫 정답 순위의 역수 | 1/2 = 0.5 | 첫 정답 A가 두 번째에 있다. 이 값을 질문마다 구해 평균한 것이 MRR이다. |
| nDCG@5 | 약 0.4982 | 이상적인 A → B → C 순서와 비교해, 일부 정답이 빠지고 뒤에 나온 정도를 점수로 표현했다. |

Recall과 Precision은 분모가 다르다. Recall은 **필요한 것 중 얼마나 찾았나**, Precision은 **가져온 것 중 얼마나 맞았나**다. Hit는 하나만 있어도 성공이고 Complete는 전부 있어야 성공이다. 그래서 Hit가 높아도 법률 답변에 필요한 근거가 부족할 수 있다.

MRR과 nDCG는 0~1 사이이며 높을수록 좋다. MRR은 첫 정답만 보고, nDCG는 여러 정답의 위치를 함께 본다. 정답들이 뒤쪽보다 앞쪽에 모이면 nDCG가 높아진다. **MRR 0.6을 정답률 60%로 읽으면 안 된다. nDCG도 정답 확률이 아니다.**

## 지표별 의미와 주의점

모든 순위 지표는 중복을 제거한 원문 조문·별표 단위로 계산한다. 양성 질문별 값을 먼저 계산한 후 평균하는 macro 방식이다. development 양성 30개와 held-out 양성 70개를 분리하며, 정답 없는 음성 질문은 순위 지표에서 제외한다.

| 지표 | 확인하려는 점 | 계산 및 한계 |
| --- | --- | --- |
| Recall@5/10 | 필요한 근거를 얼마나 회수하는가 | 상위 k개에 포함된 정답 수 / 전체 정답 수. 높을수록 좋다. 모델 선택에서 개발용 Recall@5를 먼저 본다. |
| MRR | 첫 정답이 얼마나 앞에 있는가 | 첫 정답 순위의 역수를 질문별로 평균한다. 높을수록 좋다. 전수 검색 순위를 사용하며 MRR@10은 아니다. |
| 1위 적중률 | 첫 결과가 정답인가 | 1위가 정답인 질문의 비율. 높을수록 좋다. |
| Hit@5 | 5개 중 근거를 하나라도 찾는가 | 상위 5개에 정답이 하나 이상인 질문의 비율. 높을수록 좋지만 근거가 충분하다는 뜻은 아니다. |
| Complete@5 | 필요한 근거를 모두 찾는가 | 모든 정답 조문이 상위 5개에 들어온 질문의 비율. 높을수록 좋다. 정답이 5개보다 많으면 성공할 수 없다. |
| Precision@5 | 검색 결과에 정답이 얼마나 들어 있는가 | 상위 5개 중 정답 수 / 5. 높을수록 좋지만, 정답이 하나인 질문의 최고값도 20%이므로 이 값만으로 모델을 고르지 않는다. |
| nDCG@5/10 | 여러 정답을 앞쪽에 배치하는가 | 이상적인 검색 순서 대비 점수. 높을수록 좋다. 필요한 근거의 수와 배치를 함께 반영한다. |
| 범위 안 수용률 | 자료가 있는 질문을 받아들이는가 | 검색 점수가 기준값 이상인 양성 질문의 비율. 높을수록 좋다. 자료를 실제로 올바르게 찾았는지는 위 순위 지표로 확인한다. |
| 범위 밖 오수용률 | 자료가 없는 질문도 받아들이는가 | 검색 점수가 기준값 이상인 음성 질문의 비율. 낮을수록 좋다. 분할별 음성 5개라 한 문제만 달라도 20%p가 변한다. |
| 질문 임베딩 시간 | 질문을 검색용 숫자로 바꾸는 데 얼마나 걸리는가 | 낮을수록 빠르다. 모델 실행 환경이 달라 숫자만으로 모델 속도를 단정하지 않는다. |
| 벡터 용량 | 검색용 숫자들을 저장하는 데 얼마나 필요한가 | 작을수록 저장 부담이 낮다. 비교 CSV는 숫자 자체의 용량이며 실제 DB·검색 색인 용량은 더 크다. |

nDCG는 이상적 순서의 DCG로 정규화한다는 [scikit-learn 공식 정의](https://scikit-learn.org/1.1/modules/generated/sklearn.metrics.ndcg_score.html)를 따르며, 이 실험은 단계별 관련성 대신 이진 정답을 사용한다. 같은 점수의 결과는 저장된 순위를 그대로 사용한다.

계산을 확인하려는 경우 nDCG의 DCG는 Σ rel(rank)/log2(rank+1)이며, 이를 이상적인 순서의 점수 IDCG로 나눈다. IDCG에는 검색된 정답 수가 아닌 전체 정답 수와 k 중 작은 수를 쓴다.

고정 정답 밖의 조문은 계산상 0으로 처리한다. 이는 모든 조문을 사람이 검토해 무관함을 확인했다는 뜻이 아니다. 특히 Precision과 nDCG는 정답 목록의 완전성에 영향을 받는다. 선택 기준은 처음 정한 개발용 Recall@5를 유지하고 다른 지표를 함께 해석한다.

## 지금 결과는 어떻게 읽으면 될까?

먼저 **BGE-M3 700문자의 개발용 Recall@5 65.72%**는 각 질문에 필요한 정답 근거 중 평균 약 66%를 상위 5개에서 찾았다는 뜻이다. 질문의 66%에 완벽하게 답했다는 뜻은 아니다. 같은 구성의 **Hit@5는 80%**, **Complete@5는 50%**다. 30문제 중 24문제에서는 정답을 하나 이상 찾았지만, 필요한 정답을 모두 찾은 것은 15문제다.

**KURE 500문자는 MRR 0.6245로 가장 높다.** 첫 정답을 앞쪽에 배치하는 장점이 있지만, 필요한 정답을 얼마나 많이 찾았는지까지 최고라는 뜻은 아니다. **Gemma 700문자는 nDCG@5 0.5543으로 가장 높다.** 앞쪽 5개에서 여러 정답의 배치를 함께 보면 이 구성이 유리했다는 의미다.

현재는 필요한 법령 근거의 누락을 줄이는 것을 우선해서 개발용 Recall@5가 가장 높은 BGE-M3 700문자를 우선 후보로 둔다. 다만 Gemma 700문자와 차이가 1.50%p이고 개발 질문도 30개뿐이므로 서비스 모델 확정으로 보지는 않는다. [통합 비교표](comparison.md)에서 모든 지표를 함께 확인할 수 있다.

## 아직 측정하지 않은 항목

- MAP: 여러 정답의 순서를 측정하지만 nDCG와 상당 부분 중복된다. 현재 파일의 상위 10개만으로 전수 MAP을 복원할 수 없으므로 전수 MAP으로 보고하지 않는다.
- ROC-AUC / PR-AUC: 범위 안·밖 점수 분리도 분석에 사용할 수 있으나 음성 분할당 5개로는 안정적인 일반화 판단이 어렵다. 음성 질문 유형·수를 늘린 다음 별도 검토한다.
- 신뢰구간·유의성: 같은 정답을 공유하는 질문들의 의존성을 고려한 묶음 단위 paired bootstrap 등이 필요하다. 단순 질문별 독립 가정으로 모델 우열을 확정하지 않는다.
- 생성 답변 정확성·근거 충실도: 검색 결과만으로 계산할 수 없다. 답변 생성과 인용 근거에 대한 별도 정답·검토 절차가 필요하다.
- ANN Recall·지연시간 p95: Qdrant 근사 검색과 반복 실행이 필요하다. 현재 전수 검색과 질문당 한 번의 warm 요청으로 대체하지 않는다.
