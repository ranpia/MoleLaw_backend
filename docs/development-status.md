## 현재 제한

- 일반 수집: 추가 행동 최대 4회·최종 판단, 일반 처리 3분·검색·수집 HTTP 128회·상세 법령 6건. 임베딩 누적 시간은 별도 900초다.
- 일반 법령 검색의 전체 페이지 검토가 예산 내 끝나지 않으면 해당 조건의 부분 후보를 색인하지 않는다. 로컬 ETL 진단 API와 AI Search의 페이지 제한은 별도다.
- 리랭크는 제목·시행일 기반이다. 70점·상위 2개는 초기 설정이며 법적 적합성이나 페이지 간 점수 일관성이 입증된 수치가 아니다.
- Qdrant는 설정과 일치하는 COMPLETE 세대의 서로 다른 조문 최대 15개를 반환한다. 검색 점수는 충분성 확률이 아니다.
- 후속 질문의 새로운 쟁점·최신성은 자동 재수집하지 않는다. 고정 근거 범위를 안내한다.
- 실제 usage 예산 정산, 영속 작업·중단 재개, 멱등성·분산 제어, SSE는 미구현이다.
- 최근 추론 모델은 설정·모킹 회귀만 확인했다. 계정 접근·실 API 옵션·법률 품질·비용 평가는 남았다.

## 데이터와 실험의 경계

MySQL은 업무·원문·근거·색인 상태, Qdrant는 재생성 가능한 벡터, Redis는 Refresh 상태를 담당한다. 서비스용 컬렉션과 `evaluation/` 실험 컬렉션을 섞지 않는다.

2026-10-23 요청으로 서비스용 컬렉션 3개·607포인트와 연결된 색인 기록 10건을 삭제했다. 당시 실험용 41개 컬렉션·포인트 수, 법령 원문·상담 기록 보존을 확인했다. 이는 당시 정리 기록이며 현재 실시간 수량은 아니다. 다음 서비스 벡터화에서 컬렉션을 다시 생성한다.

KURE-v1·1024차원은 현재 구현·검증용 설정이다. 실험 브랜치 결과를 서비스 품질 합격이나 최종 모델 선정으로 간주하지 않는다.

## 분리된 HTTP 호출 예산

검색·법령 API·Qdrant 검색은 기존 최초 상담 128회 한도를 사용한다. 모델 정보 조회·질문/문서 임베딩은 APP_LAW_VECTOR_EMBEDDING_MAX_CALLS(기본 1024회), 컬렉션 준비·적재·저장 검증·완료 세대 재검증은 APP_LAW_VECTOR_INDEXING_MAX_CALLS(기본 1024회)를 각각 실행 전체에서 누적한다. 법령·배치마다 초기화하지 않으며 한 실행에서 설정을 높이거나 바꾸지 못한다. 임베딩의 별도 누적 900초·일반 처리 시간·행동 한도는 유지한다.

모델 revision 조회는 법령 색인 세션의 첫 배치에서 수행하고 이후 배치는 생략한다. 새 법령·새 재색인 세션 또는 배치 실패 후 재시도에서는 다시 검증한다. 각 배치의 응답 모델명·차원·유한값·정규화 검증과 최종 Qdrant 저장 검증은 유지한다. 오류 로그 call budgets의 retrievalUsed/embeddingUsed/indexUsed와 exhausted로 소진 구분을 확인한다. calls는 세 종류의 총 HTTP 횟수이며 LLM 토큰 예산과 별개다.
