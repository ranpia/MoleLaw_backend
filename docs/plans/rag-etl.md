# RAG·ETL 후속 작업

연결 작업: [P04·P05·P06](README.md). 실행 계약은 [벡터 Tool](../law-vector-tools.md)과 [ETL](../law-etl-local.md)을 따른다.

## 구현된 기준선

기존 법령 API Tool→MySQL 불변 원문→Reader→Transformer→Writer→HTTP 임베딩→Qdrant를 연결했다. 쓰기 후 포인트·payload·실제 벡터를 검증하고 COMPLETE만 검색한다. 동일 완료 색인 재검증·재사용과 누락 시 새 세대 재처리를 제공한다. QdrantVectorStore.add를 통한 중복 임베딩은 하지 않는다.

현재 KURE 설정은 1024차원·고정 revision, 300 코드포인트 청크·64 중첩·배치 16이다. 최종 품질 선정값이 아니며 임베딩 모델 변경은 새 컬렉션·설정 fingerprint로 분리한다. Ollama 후보 비교는 별도 실험이고 현재 서비스 런타임과 혼동하지 않는다.

## P04 — 검색·버전

실제 법령명·조문번호 질의의 dense 검색 실패를 측정한 뒤 정확 일치·키워드/BM25·RRF·질의 확장 등을 비교한다. 모든 개선을 동시에 넣지 않는다. 질문 임베딩 재사용과 새 색인 후 재검색을 구분하고, 사건 기준일·시행일 혼합은 D03 정책으로 검증한다.

조·항·호·목·가지번호·삭제 조문·부칙·긴 조문 파싱 누락을 fixture로 보강한다. 검색 품질과 원문 파싱 정확도를 분리해 보고한다. 모델·청킹 최종 채택은 D05와 P02 결과를 따른다.

## P05 — 영속 복구와 정리

수집 페이지·작업·배치 완료 위치, WRITING 회수와 재시도를 영속화하는 방안을 설계한다. 지금의 재색인은 원문 전체를 새 세대로 처리하며 배치 중간 재개가 아니다.

분산 중복 실행·사용자 취소·연결 종료·전체 deadline·늦은 결과 저장을 제어한다. 비동기 전환은 D04 결정 후 별도 계약으로 만들고 SSE는 후순위로 유지한다.

FAILED·비활성 세대의 물리 삭제는 활성 세대·진행 중 작업·원문·상담 근거 참조를 확인한 뒤 수행한다. 실험 컬렉션을 정리 대상에 포함하지 않는다. 보존 기간은 D09에서 정하며 이번 문서는 데이터 삭제를 실행하지 않는다.

## P06 — 판례와 후속 대화

판례 검색·상세 Tool은 구현되어 있지만 상담의 자동 판례 본문 수집·채택 흐름은 별도다. D06 범위에 따라 판시사항·요지·참조조문·판례내용을 검증하고 제목·메타데이터만을 법적 결론 근거로 사용하지 않는다.

후속 상담의 Advisor·성공 턴 저장·최초 근거 고정은 유지한다. 메시지 수 창을 실제 토큰 창으로 보강하고 DB 페이지 조회·완결 턴·사실 정정·동시 요청을 검증한다. 후속의 법령 재수집·ETL과 동의 전 외부 판례 호출은 0회여야 한다. 승인 후 판례 호출은 방 근거·호출·본문 예산 안에서 검증한다.

## API Tool 경계

법령·판례 Tool 도입과 서버 검증 실행 방식은 [확정 결정](../decisions/confirmed.md)이다. 새 클라이언트를 중복 구현하거나 모델에게 임의 URL·소유권·실행 예산을 맡기지 않는다. SerpApi와 AI Search는 [P07](README.md)의 별도 검토 대상이다.
