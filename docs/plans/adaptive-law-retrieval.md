# 근거 부족 시 법령 추가 수집·재검색 개발 계획

2026-10-19 작성. 미구현 개발 계획이다. [RAG·ETL 계획](rag-etl.md)의 최초 질문 처리 흐름을 구체화한다. 후속 질문은 기존 근거만 사용하는 경계를 유지한다.

## 목표와 판단 흐름

현재 Qdrant 검색 결과를 LLM이 검토하고, 답변 근거가 부족하면 필요한 법령을 수집·벡터화한 뒤 다시 검색한다. 낮은 유사도만으로 미수집 법령이라고 판단하지 않는다. LLM의 판단은 제안이며 수집 여부·버전·실행 예산은 서버가 확인한다.

| 판단 | 처리 |
| --- | --- |
| 현재 근거로 답변 가능 | 적용 기준일과 근거를 확인하고 답변 생성 |
| 기존 자료 재검색 필요 | 의미를 보존해 질의를 바꾸거나 법령명·조문 필터로 재검색 |
| 법령 추가 수집 필요 | 법령 목록·수집 상태·버전을 확인하고 공식 원문 수집 → ETL → 색인 → 재검색 |
| 다른 정보 필요 | 개인 사건 사실은 확인 질문, 지원하지 않는 관할은 범위 안내, 외부 조회 장애는 실패 사유 안내 |

미수집 여부는 MySQL의 법령 ID·MST·시행일·본문 해시·활성 색인 상태로 확인한다. 검색 실패와 자료 부재를 구분하고, 필요한 법령명이 불명확하면 공식 목록에서 후보를 확인한다. LLM이 제시한 법령명·조문·임의 URL을 검증 없이 근거로 사용하지 않는다.

## 구현 순서

- [ ] 질문 정제 후 기존 활성 색인을 검색하고 근거 조문·버전·출처를 확보한다.
- [ ] LLM이 위 네 가지 판단과 부족한 쟁점·필요한 자료·판단 이유를 구조화해 반환하도록 한다. 세부 출력 스키마와 프롬프트는 구현 시 고정한다.
- [ ] 서버가 수집 목록과 대조한다. 이미 있는 동일 버전은 재검색하고, 누락·변경 자료만 기존 법령 Tool과 ETL 경로로 처리한다.
- [ ] 동일 법령 버전의 동시 수집을 합치고, 준비 중인 색인은 제외한다. 변경 없는 본문은 임베딩을 생략하며 실패 작업은 재개한다.
- [ ] 새 색인이 활성화되면 재검색하고 충분성을 다시 판단한다. 같은 질의·색인 상태를 반복하지 않는다.
- [ ] 시간·외부 호출·임베딩·LLM 토큰 예산과 진행 여부로 종료한다. 수치 상한은 자원 측정 후 정하며, 소진 시 확보한 근거와 부족 사유를 남긴다.
- [ ] 최종 근거·법령 버전·조회 시점과 판단 이력을 스냅샷으로 보존한다. 법령 추가 수집이 불가능한 질문을 반복 벡터화하지 않는다.

MySQL을 원문·수집/색인 상태의 원본으로, Qdrant를 재생성 가능한 검색 색인으로 유지한다. 모델·차원·입력 형식·청킹 버전이 다른 벡터는 섞지 않는다. 임베딩 실험 결과와 모델 선정 기록은 `experiment/legal-embedding-evaluation` 브랜치에서 관리하며, 이 문서 반영은 서비스 모델 전환을 의미하지 않는다.

## 검증과 완료 조건

판정용 정답은 모델 출력과 독립적으로 검토해 고정한다. 실제 서비스 LLM의 질문 정제와 충분성 판단을 포함해 평가하며, 고정 색인 검색 지표와 동적 수집 전체 흐름의 성능을 따로 보고한다.

- [ ] 충분한 근거, 표현 차이로 인한 검색 실패, 미수집 법령, 오래된 버전, 해외 관할, 개인 사건 정보 부족, 외부 API 장애를 구분하는지 확인한다.
- [ ] 판단 유형별 정확도·오분류, 불필요한 수집 비율, 필요한 수집의 누락 비율을 측정한다.
- [ ] 수집 전후 Recall@5·Complete@5, 최종 인용의 충실성, 근거 부족 상황에서 부당하게 답하는 비율을 측정한다. 유사도 임계값 통과율을 실제 답변 오답률로 해석하지 않는다.
- [ ] 지연시간·호출/토큰/임베딩 비용, 중복 수집, 부분 실패 복구·버전 혼합·예산 종료를 검증한다.
- [ ] 후속 질문에서 수집·ETL·외부 검색 호출이 0회인지 검증한다.

합격 수치와 기본 예산은 독립 평가셋과 기준선을 확보한 뒤 확정한다. 검색 단계의 통과만으로 답변 품질이나 서비스 배포 준비가 완료되었다고 판단하지 않는다.
