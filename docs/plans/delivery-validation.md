# 구현 순서와 검증 계획

상위 문서: [재구축 요약](../backend-rebuild-plan.md). 상태 기준: 2026-10-13.

## 현재 구현과 목표의 구분

완료된 기반은 Spring AI 1.0.9 ChatClient·EmbeddingModel 통합, MySQL/Qdrant 프로필 분리, H2 테스트 격리, 법령 회귀 fixture, MySQL/Qdrant/Redis Compose다. Redis 컨테이너 실행은 JWT 저장소 구현 완료를 의미하지 않는다.

법령/판례 내부 Tool·검색 옵션·원문 스냅샷과 CPU Ollama 환경을 검증했다. Redis Access 등록 방식은 유지하며 2026-10-14 Redis Refresh 해시·원자 회전·재사용/경합·폐기·JSON 제거를 구현했다. ETL·Spring Ollama/Qdrant 검색·Advisor·상담방 근거·Access stateless/issuer/audience·역할별 오케스트레이터는 미구현이다. 현재 Refresh 완료 범위와 일반 156개·실제 Redis 11개·MySQL 2개 검증은 [구현 문서](../refresh-rotation.md)를 따른다.

## 단계와 완료 조건

MySQL 초기 기반: 기존 데이터 이관 없이 Flyway V1으로 빈 DB를 생성하고 기본/local을 validate로 통일했다. `mysqlIntegrationTest`는 별도 임시 MySQL에서 스키마·JPA·원문/암호문·제약·재기동을 검사한다. ETL·상담 근거 스키마까지 완료한 것은 아니다. 인증 family/Refresh는 Redis가 소유하며 MySQL 테이블을 추가하지 않는다. [실행 가이드](../mysql-setup.md)를 따른다.

## 검증을 나누는 기준

- **단위·회귀:** 외부 호출 모킹, 합성 법령 fixture, 빈 결과·시간 초과·권한·중복·청크 ID 검증. `.\gradlew.bat test`로 실행한다.
- **저장소 통합:** 실제 MySQL/Qdrant/Redis에서 마이그레이션·삭제·회전·부분 실패를 검증한다. H2나 컨테이너 상태 검사로 대체하지 않는다.
- **인프라 상태:** `powershell -NoProfile -ExecutionPolicy Bypass -File docker/verify.ps1`. 임시 데이터로 연결·인증·기본 동작만 확인한다.
- **모델 품질:** 고정된 30~50개 질문에 법령/조문 지정·일상 표현·복합 쟁점·부족 근거·후속 사실 정정을 포함한다. 프롬프트 예시와 평가 질문은 분리한다.

평가 결과에는 질문셋 버전, 원문/색인 버전, 모델 ID/digest, 프롬프트·옵션, 하드웨어, 실제 토큰·비용·지연을 기록한다. 검색 Recall@K·무관 문서 비율, 인용 정확도·무근거 주장·근거 부족 처리와 p95 지연을 비교한다. 정적 검색과 동적 수집 실험은 분리한다. 합격 수치는 기준선 확보 후 구현 PR 전에 확정한다.

## 운영·복구에서 보완할 작업

- 요청/상담방/수집/색인 작업/모델 역할에 추적 ID를 연결한다. 토큰·민감 질문·외부 응답 원문은 로그에 남기지 않는다.
- 외부 API/모델 호출에 전체 deadline과 개별 timeout·제한 재시도·동시성 상한을 둔다. 사용자 취소·연결 종료 후 작업 지속/중단 정책도 정한다.
- 동기 최초 질문이 예산을 넘길 때 오류 반환과 비동기 상태 조회 중 하나를 선택하고 프론트 계약을 문서화한다. SSE나 작업 큐는 아직 확정하지 않는다.
- MySQL 백업 복원→Qdrant 재색인→활성 색인 전환을 검증한다. Redis Refresh 유실 시 재로그인하고 기존 Access는 만료까지 유지된다. 오래된 복원 상태의 폐기 토큰 부활 방지는 인증 계획을 따른다.
- 삭제된 상담방의 진행 중 작업이 메시지/근거를 다시 생성하지 않도록 완료 저장 시 상태를 재확인한다. 기록·근거 보존 기간과 계정 탈퇴 삭제 범위를 정한다.
- 법령 시행일·조회 시점·적용 범위를 응답에 표시하고, 근거 부족을 법적 결론으로 단정하지 않는다. 오래된 방의 스냅샷을 자동 교체하지 않으며 새 상담을 안내한다.

## 배포·기존 코드 정리

`FinalAnswer`의 검색/프롬프트/모델/출처 책임과 중복 호출을 분리한다. 목록 N+1·정렬·지연 로딩·암호화 키 관리도 점검한다. 긴 외부 호출을 DB 트랜잭션 밖에서 실행한다.

기존 LawEmbedding 경로는 새 경로 검증 후 제거한다. 스키마 전환은 백업·검증·복구 방법을 포함하고 대량 삭제/초기화는 별도 작업으로 취급한다. 운영 배포는 현재 Compose 검증과 별개이며 배포 설정·비밀값·TLS·헬스체크·롤백을 준비한 뒤 진행한다.

## 검증 이력

기존 문서의 테스트 20개/build 통과는 과거 이력이다. 2026-10-07 Compose에서 MySQL 쿼리, Qdrant 인증·벡터 검색, Redis 인증·TTL·삭제를 검증했다. 이번 문서 재구성으로 애플리케이션 구현이나 검증 완료 범위를 확대하지 않는다.
