# 계획 분리와 병렬 검토 결과

검토일: 2026-10-12. RAG·ETL, 인증·보안, 오케스트레이션·모델을 세 에이전트가 나누어 검토하고 주 에이전트가 요약·실행 계획과 통합했다. 문서 보완 결과이며 기능 구현·실제 모델 평가 결과는 아니다.

## 보완한 항목

| 영역 | 누락·위험 | 계획에 추가한 대응 |
| --- | --- | --- |
| 법령·근거 | 개정 버전 혼합, 기준일 불일치 | MST·시행일 구분과 원문 스냅샷, 버전 충돌 평가 |
| 기존 상담 | 최초 근거가 없는 과거 방 | 이관/제한 안내 정책을 구현 전 결정 |
| 비동기 작업 | 취소·삭제 후 늦은 결과 저장 | 상태 재확인, 실행 식별자와 결과 저장 차단 |
| 인증 폐기 | Redis 반영 실패·회전 경합 중 세션 생존 | 부분 실패 차단 보장과 세션 버전/폐기 시각 검증 |
| 재발급 | 동시 탭·응답 유실·무한 재시도 | 한 번 소비, 재시도/재로그인 계약, 서비스 오류 구분 |
| 모델 실행 | 역할별 재시도로 호출·비용 증폭 | 공유 예산 예약/정산, 재시도 책임 통합 |
| 에이전트 안전 | 잘못된 근거 ID·문서 지시문·검증 생략 | 구조화 계약, 허용 도구/ID 검증, 실패 정책 |
| 평가·전환 | 재현 불가·개선 없이 복잡성 증가 | 버전 고정·단계별 비교·단일 RAG 복귀 |
| 운영·데이터 | 복구·보존·외부 전송 범위 불명확 | 백업/재색인 복구, 보존·탈퇴·최소 전송 정책 |

## 남은 결정

수치 예산·품질 합격선, 동기/비동기 응답, 법령 적용일 범위, 기존 상담방 처리, Refresh 동시성/응답 유실, 개인정보 보존 정책은 아직 미확정이다. 관련 단계 구현 전에 각 상세 계획에서 결정과 검증 방법을 함께 기록한다.

## 스킬 대신 계획으로 둔 이유

현재 내용은 구현 전 설계·선택 사항이다. 이를 스킬로 고정하면 검증하지 않은 정책이 반복 실행 지침으로 굳어질 수 있다. ETL 재색인·RAG 평가·인증 회귀 검증이 구현되고 실제 명령/입출력/실패 복구가 확정되면 그 절차를 스킬로 추출한다. 이번에는 스킬이나 AGENTS.md를 생성·수정하지 않는다.

최신 진입점은 [재구축 요약](../backend-rebuild-plan.md)이며 보관본은 실행 지침으로 사용하지 않는다.
