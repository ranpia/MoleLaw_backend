## 별도로 실행했던 검증

- 실제 MySQL·Redis·격리 Qdrant 통합은 각 실행 문서의 날짜별 기록을 따른다. H2로 대체하지 않는다.
- 실제 KURE로 통제된 조문·청크 저장과 상위 조문 검색을 확인했고, threaded 서버의 상태 응답·추론 부하 제한을 확인했다. 실제 법률 검색 합격을 뜻하지 않는다.
- Postman 임베딩 대역·격리 Qdrant로 ETL·누락 포인트 복구·최초 상담 저장을 검증했다. LLM·법령 API의 대역 응답은 품질 근거가 아니다.
- AI Search는 정상·빈·잘못된 응답·404의 모의 검증만 확보했다. 실 API에서는 404가 관측됐고 원인은 미확인이다.
- 과거 GPT-4 판단 계약 실호출은 네 상태의 계약 경로 확인이다. 새 모델이나 실제 상담 품질 평가로 재사용하지 않는다.

## 실 상담 실패와 호출 예산 분리 — 2026-10-23

크레딧 문제 해소 후 gpt-5.4-mini 질문 분류 직접 호출은 HTTP 200·1043토큰이었다. 최신 별도 서버의 실 상담에서도 분류를 통과했지만 최초 실행은 두 번째 충분성 판단의 FIELD_CONSTRAINT에서 종료됐다. 원래 모델 출력을 저장하지 않아 구체 위반 필드는 확정하지 않았다. 판단 프롬프트에 목록 개수·길이·부처 코드 제약을 명시하고 값 없는 크기/건수 진단을 추가했다.

수정 후 실행 e2acd00b-0679-4947-aae2-c83a9a2b6ce5는 공항시설법을 선택해 실제 KURE·Qdrant로 228청크를 저장·검증하고 조문 15개를 재검색했다. 다음 국토계획법 전체 색인 중 기존 공유 HTTP 128회가 소진돼 종료됐다. 첫 답변 생성·방 저장 성공으로 기록하지 않는다. 임시 계정 정리는 테스트 스크립트에서 수행한다.

이후 검색/수집·임베딩·색인의 HTTP 카운터와 한도를 분리했다. 일반 최초 상담 검색/수집 128회, 임베딩·색인 각각 기본 1024회이며 한 실행 안에서 누적한다. 모델 revision은 법령 색인 세션의 첫 배치에서 확인하고 새 세션·실패 후에는 재검증한다. 각 배치 벡터 검증과 완료 세대 공개 조건은 유지한다.

검증 결과: 일반 369개·실패 0·건너뜀 2, bootJar 성공. lawEtlSimulationTest 2개·initialConsultationSimulationTest 1개 모두 실패·건너뜀 없이 통과했다. 대형 합성 조문의 128개 초과 청크 적재·포인트 누락 복구·재검색을 검색 예산 4회만으로 완료했고, 임베딩/색인 횟수가 각각 128회를 넘어도 별도 누적됨을 확인했다. 모델 확인 1회/세션·실패 후 revision 재검증, 예산별 상한·중간 한도 변경 금지·후속 금지도 검증했다.

이 분리 변경 뒤 실제 공항 질문은 추가 재요청하지 않았다. 사용자가 요청·로그 확인을 맡았으며 실행 중 서버는 재시작해야 새 코드가 적용된다. 검증용 Postman 대역과 격리 테스트 컨테이너는 종료했다. 원문·서비스/실험 컬렉션·사용자 서버는 삭제하거나 중지하지 않았다.
