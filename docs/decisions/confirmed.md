# 확정한 결정

2026-10-26까지의 사용자 지시와 현재 구현 기준이다. 중간에 바뀐 선택은 최신 계약만 적고 과거 설계는 [보관 자료](../archive/README.md)로 분리한다.

| 항목 | 확정 내용 | 현재 상태·근거 |
| --- | --- | --- |
| 브랜치 | 작업은 dev에서 진행. 검증한 통합본을 main에 반영하고 배포는 수동 | main 반영·배포는 별도 작업 |
| 저장소 | MySQL 업무·원문·대화, Qdrant 벡터, Redis Refresh | [인증](../auth/stateless-access.md), [스키마](../database/schema-rebuild-status.md) |
| 초기 DB | 기존 데이터 이관 없이 새로 시작 | Flyway V1~V5. 실행 중 DB의 임의 재초기화 권한을 뜻하지 않음 |
| 최초 질문 | 필요한 법령 수집·ETL·재검색 허용 | 서버 권한·호출·시간 한도 유지 |
| 복합 질문 품질 | 질문 의도 구조화, 승인한 수집 조건 유지, 질문·법령별 후보 균형을 적용 | [분석·수집·균형 계약](../law/question-routing.md) |
| 답변 완결성 검사 | 각 질문에 최종 답변했는지를 별도로 검사하는 4번 항목은 보류 | 기존 충분성 판단·서버 인용 검증은 유지 |
| 예산 산정 시점 | 기능 구현 후 최종 산정, 현재는 정보 보존과 답변 품질 우선 | 사용량 계측 유지. 로컬 처리 시간 확대는 품질 검증용 임시 설정 |
| 전환 판단 | 재검색·추가 법령 수집·답변 가능 여부는 LLM이 제안 | 서버가 계약·권한·예산·인용을 검증 |
| 일반 법령 리랭크 | 전체 페이지를 검토하고 기준 미달은 상세 조회·임베딩 제외 | AI Search 제외. 70점·상위 2개는 현재 초기값 |
| ETL | 기존 법령 Tool과 HTTP 임베딩 서버 재사용, Reader→Transformer→Writer | 쓰기 후 저장 검증을 통과해야 COMPLETE 공개·재검색 |
| 근거 읽기 | 전체 후보 목록을 먼저 비교하고 선택한 본문만 별도 예산으로 읽은 뒤 충분성 판단 | 최초 수집에 적용, 읽은 ID만 승인·인용 |
| 후속 상담 | Advisor로 방 기록 복원, 최초 법령 유지. 새 판례 보강은 사용자에게 먼저 묻고 요청별 명시 동의 후 방 법령 근거로 검색·읽기 | 인용한 판례만 방에 누적. 법령 재수집·ETL 금지. [계약](../chat/follow-up-consultation.md) |
| 판례 검색 의도 | 지정 사건 자체의 판결인지 유사 쟁점 판례인지는 LLM이 판단. 사건 식별어·후보 선택·본문 평가에 그 목적 유지 | 서버는 명칭 규칙으로 분류하지 않고 관측 식별어·후보 ID·권한·인용을 검증. [검색 흐름](../law/case-retrieval-reranking.md) |
| 예산 | 실제 LLM 토큰 usage를 서버 알고리즘으로 정산 | 정산 구현·수치 정책은 남음. LLM에게 비용 결정을 맡기지 않음 |
| 임베딩 제어 | 처리량·동시성·대기열·별도 시간 한도 관리 | 로컬 단일 추론·유한 대기열 구현, 분산 제어 미완료 |
| 상태 통신 | SSE는 나중에 추가 | 현재 동기 API 유지 |
| 모델 배정 | 분류·리랭크 gpt-5.4-mini/low, 충분성 gpt-5.4/medium, 답변 mini/medium | 설정 반영. 실 API·품질 채택 검증과 구분 |
| AI Search | 코드 준비·비교 가능하게 유지, 실 API 재시도 보류 | 기본 QDRANT. 404 원인은 미확인 |
| 컬렉션 정리 | 서비스 구축·검증용만 삭제하고 실험용 보존 | 2026-10-23 정리 완료. 향후 실험 데이터 삭제 승인으로 확대하지 않음 |

Access Redis 저장·MySQL Refresh 테이블이라는 과거 제안은 현재 계약이 아니다. 현재 Access는 모든 프로필 5분 stateless, Refresh는 Redis 난수 토큰 회전이다. JWT에 상담방 목록을 넣는 제안은 보류 상태이며 구현 범위에 포함하지 않는다.
