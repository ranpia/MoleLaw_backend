# 후보 목록과 조문 본문 읽기

기준일: 2026-10-23. 최초 상담의 충분성 판단 전에 목록 비교와 본문 읽기를 분리했다. 후속 상담의 Advisor·고정 근거는 변경하지 않는다.

## 호출 순서

1. 기존 검색에서 받은 최대 15개 조문의 ID·종류·제목·법령ID·조문 경로·시행일·예상 본문 토큰 수를 candidateCatalog로 구성한다. 본문·URL은 목록 선택 모델에 보내지 않는다.
2. evidenceReadChatClient가 목록 전체를 비교해 한 번에 최대 8개 ID를 선택한다. 질문과 쟁점·법령별 범위, 남은 본문 예산을 보고 고른다.
3. EvidenceReadToolService.readEvidence가 현재 검색 후보 ID 소속을 먼저 검증한다. Qdrant 후보는 MySQL의 같은 불변 원문 UUID·MST·법령ID·시행일·출처에서 조문을 복원하고 검색 후보 본문·제목과 일치하는지 확인한다. 새 법령 API·임베딩은 호출하지 않는다.
4. 조문 전체가 예산에 들어가면 READ, 초과하면 BODY_BUDGET_EXCEEDED로 기록한다. 잘라낸 본문을 전체 조문으로 전달하지 않는다.
5. 필요 시 목록 선택을 한 번 더 실행한다. 이미 시도한 ID는 다음 후보 목록에서 제외한다. 모델이 재선택해도 중복 읽기 없이 건너뛰며 새 ID가 없으면 기존 본문을 보존하고 종료한다. 실제 본문 읽기는 각 충분성 판단 준비마다 최대 2라운드다.
6. 충분성 Client에는 후보 목록·읽기 결과와 실제 읽은 본문을 함께 제공한다. evidence의 ID만 승인·인용 가능하며 목록에만 있는 ID는 거절한다.

조문 본문은 항·호·목·단서를 포함한 기존 파서의 전체 articleText다. 항만 선택해 읽거나 인접 조문·참조조문을 자동 확장하는 기능은 아직 없다. 필요한 참조는 현재 검색 후보 범위에 있어야 하며 임의 원문 UUID·법령 전체를 읽는 권한을 모델에 제공하지 않는다.

## 분리된 입력 상한

| 입력 | 환경변수 | 기본값 |
| --- | --- | ---: |
| 질문·계획·검색 이력 등 판단 기본 JSON | APP_AI_EVIDENCE_MAX_INPUT_TOKENS | 2500 |
| 목록 선택의 질문·계획·전체 목록·읽기 이력 JSON | APP_AI_EVIDENCE_CATALOG_MAX_INPUT_TOKENS | 4000 |
| 한 판단 준비의 누적 본문·근거 직렬화 추정량 | APP_AI_EVIDENCE_BODY_MAX_INPUT_TOKENS | 12000 |
| 최종 충분성 판단의 결합 입력 JSON | APP_AI_EVIDENCE_DECISION_MAX_INPUT_TOKENS | 20000 |

cl100k_base의 로컬 추정치이며 공급자의 실제 청구량이 아니다. 본문량은 출처 메타데이터를 포함해 보수적으로 계산하고, 결합 입력은 실제 evidence view 전체를 다시 검사한다. 시스템 프롬프트·출력·숨은 추론 토큰은 별도다. 요청 전체 실제 usage 정산·예약·비용 차단은 P03의 미구현 작업이다.

본문 읽기 선택 모델은 gpt-5.4-mini/low, 완료 토큰 한도 4096이다. APP_AI_READ_MODEL·APP_AI_READ_REASONING_EFFORT·APP_AI_READ_MAX_COMPLETION_TOKENS로 바꾼다. 자동 모델 승격이나 무한 읽기 반복은 없다.

## 근거와 실패 경계

- candidateCatalog는 발견 목록이다. 제목만 보고 법적 주장을 승인할 수 없다.
- 읽기 선택의 미등록 ID·한 응답 안의 중복 ID·잘못된 JSON은 실패한다. 이전 라운드 ID 재선택은 건너뛴다.
- MySQL 원문 버전·제목·본문이 후보와 다르면 실패한다. 다른 시행 버전이나 최근 원문으로 대체하지 않는다.
- 예산 초과는 법령 부재와 다르다. 이를 해결하려고 같은 법령을 다시 수집·임베딩하지 않도록 판단 프롬프트에 명시했다.
- 첫 목록 입력 자체가 상한을 넘거나 결합 판단 입력이 상한을 넘으면 근거 부족으로 종료한다. 두 번째 목록 입력만 초과하면 추가 선택을 생략하고 이미 읽은 본문을 보존한다.
- 실제 읽은 본문과 같은 ID의 승인 근거만 최종 답변·방 스냅샷에 남긴다. 후속은 해당 스냅샷을 사용하고 읽기 Tool을 새로 제공하지 않는다.

AI Search 후보는 Tool이 이미 검증한 불변 본문을 현재 후보 안에서 읽는다. 실제 AI Search 재시도는 보류하며 일반 법령 검색의 전체 페이지 리랭크와는 별개다.

## 진단과 검증

실패 로그는 MODEL_SELECTION·SELECTION_CONTRACT·SOURCE_READ 단계를 구분한다. 원시 모델 응답은 기록하지 않는다. Evidence reading 로그의 candidateCount/readCount/deferredCount/bodyTokens와 local 판단 진단의 candidateCatalog·readOutcomes·visibleEvidence를 함께 확인한다. BODY_BUDGET_EXCEEDED를 미수집이나 관련성 탈락으로 해석하지 않는다. 원문 본문·상담 질문·원시 모델 출력은 로그에 추가하지 않는다.

목록 15개 전체 비교, 여러 본문 선택, 긴 조문 제외 후 짧은 후보 읽기, 미등록 ID 차단, 원문 변조/버전 불일치, 읽지 않은 ID 승인 차단, 결합 상한을 회귀 검증한다. 모의 최초 상담·AI Search 경로와 실제 법률 품질 평가를 구분한다. [검증 현황](validation-status.md)·[후속 계획](plans/README.md)을 따른다.

사용자에게 확인 질문을 받아 상담 초안을 이어가는 기능은 이 변경과 별개이며 아직 구현하지 않았다. 읽기 선택을 분리한 것만으로 검색 후보의 법령 다양성이나 법률 답변 정확성이 보장되지는 않는다.
