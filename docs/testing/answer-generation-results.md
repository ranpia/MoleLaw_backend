## A: 비용 없는 스트림·장애 검증

`run-answer-stream-simulation.ps1`이 Postman 시뮬레이션과 직접 연결용 동일 Node 대역을 띄운 뒤, 실제 Spring AI HTTP 어댑터와 앱 컨트롤러/서비스·H2 저장소를 실행한다. 외부 모델·법령 수집·임베딩을 호출하지 않는다. 근거 수집과 제목 추출만 합성 대역이며 실제 모델 제공자의 처리량/과금을 재현하는 자료는 아니다. 백엔드 수신은 MockMvc 비동기 경로이므로 외부 서버의 네트워크/프록시 부하 검증과 구분한다.

최종 `answerStreamSimulationTest`는 **14건, 실패/건너뜀 0**이다.

- NDJSON/SSE의 조기 delta, JSON 문자열의 따옴표/개행, terminal 이벤트 1회와 마지막 위치를 확인했다. 최종 요청을 완료하기 전에 delta를 받아도 방/메시지 저장은 0건이었다.
- 검증된 완료 뒤 방 1개·메시지 2개와 SAVED/completed를 확인했다. 무저장 동시 1/2/4개는 방을 만들지 않았다.
- 4개를 의도적으로 유지한 뒤 5번째는 RETRIEVAL_BUSY였고 모델 HTTP 호출 수는 늘지 않았다. 해제 후 새 요청 성공을 확인했다.
- 429·503·잘못된 인용·빈 응답·깨진 JSON·잘린 스트림·중간 정지에 error가 발생하고 completed/저장이 없었다. 각 실패 뒤 새 정상 요청이 성공했다. 시험용 앱 timeout은 5초이며 기본 20분 설정을 바꾸지 않았다.
- 직접 대역 취소에서 앱→모델 어댑터 취소 전파, 미저장과 슬롯 재사용은 확인했다. **대역의 응답 연결은 즉시 닫히지 않을 수 있었다.** 따라서 로컬 취소를 공급자의 계산/과금 중단으로 보장하지 않는다. 이 시험은 브라우저/TCP 연결 해제 전체를 재현한 것이 아닌 서비스 구독 취소 검사다.

초기 조기 전송 검사는 대역이 첫 조각 하나만 보내고 멈춰 실패했다. 로컬 Spring AI 1.0.9 소스의 2개 조각 버퍼를 확인하고 역할/본문 여러 조각을 보낸 뒤 대기하도록 대역을 수정했다. 이후 Postman 경로에서도 조기 전송을 확인했다. 이를 Postman 스트리밍 불가나 앱의 완료 후 일괄 전송 문제로 보고하지 않는다. Postman 중계 경로와 직접 연결의 취소 관측은 별도로 구분한다.

전체 회귀에서는 기존 후속 상담의 FOLLOW_UP_ROUTING 진행 이벤트 누락과 MockHttpServletResponse 헤더 맵의 동시 수정 실패를 발견했다. 진행 이벤트는 주 스트림의 준비 순서에 포함하도록 보완했다. MockMvc 테스트에서는 보안 헤더를 초기 필터 단계에서 쓰도록 해 비동기 쓰기와의 충돌을 피했다. 보안 헤더를 제거하거나 운영 인증·CSRF 정책을 완화하지 않았다. 실제 답변 모델의 인용 형식 실패와는 별개다.

보완 후 전체 JUnit **546건, 실패/건너뜀 0**을 확인했다. 기본 전체 테스트에는 유료/시뮬레이션 tag가 포함되지 않으므로 실제 모델의 인용 실패를 전체 회귀 성공으로 덮어쓰지 않는다.

```powershell
.\scripts\load-testing\run-answer-stream-simulation.ps1
```

Node·Postman CLI·JDK 17이 필요하다. 기본 포트 14241/14242가 사용 중이면 실행을 거절한다. 도구가 시작한 프로세스만 finally에서 종료한다. 최종 재확인 로그/XML은 Git 제외 `build/answer-stream/20261029T071923Z/`, Gradle 보고서는 `build/reports/tests/answerStreamSimulationTest/`에 있다. 합성 자료 외에는 시뮬레이션에 보내지 않는다. ## B 최초 실행: 실제 인용 실패 기록

앱의 답변 ChatClient 설정·system prompt·EvidencePromptBuilder·CitationValidator를 재사용하는 별도 opt-in Gradle 도구를 추가했다. DB·수집·임베딩·리랭킹·도구 호출은 없다. 실제 공개 법령의 고정 Qdrant 후보에서 q01/q11/q17, 근거 3/8개 fixture를 구성했다. expert gold 품질셋은 아니며 과거 시행일 스냅샷 조건을 질문에 명시했다.

- 모델 `gpt-5.4-mini`, effort medium, 최대 완료 4,096토큰, 요청 전체 180초 제한. 소스 기본 16,384와 다른 시험 조건이다.
- 자동 retry는 1회 시도 설정이며 실제 HTTP 출발 filter가 시도를 계수·예약한다. full prompt UTF-8+메시지 여유분 40,000바이트 상한과 출력 4,096의 보수적 비용을 요청당 USD 0.05로 예약한다. 최대 30시도/USD 5를 넘는 요청을 시작하지 않는다. 두 실행을 합쳐 실제 시도는 6회다. 이 제한은 **이 도구 실행 안에만** 적용되며 앱 전체 보조 모델 호출의 전역 예산 기능을 구현한 것은 아니다.
- 사용량이 없거나 요청이 실패하면 예약을 0원으로 해제하지 않는다. usage가 있으면 입력을 캐시 할인 없이 정산해 보수적으로 추정한다. 실패 시 새 작업을 중지하고 대기 중인 후속 작업도 추가 HTTP 출발을 차단한다. 이미 진행 중인 요청까지 공급자 계산이 중단된다고 보장하지 않는다.
- 스트림의 실제 usage와 reasoning/cache 내역, 첫 모델 텍스트·완료·종료 사유·입력 해시를 기록한다. 앱 answer_delta/저장 완료 시간과 다른 **생성 단독 시간**이다. 실제 청구 금액이나 법률 정확도 검증을 대신하지 않는다.

가격은 2026-10-29 확인한 [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.4-mini)의 표준 1M토큰당 입력 USD 0.75·출력 USD 4.50을 기준으로 했다. [공식 스트리밍 문서](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)에 따라 include_usage를 요청했다. 종료/취소 시 usage 누락 가능성을 고려한다. 향후 재실행 전 요금·모델·프로젝트 제한을 다시 확인한다.

| --- | --- | --- | --- | --- |
| smoke 1 | q01·근거 3 | 6.673초 | 9.841초 | 성공 |
| smoke 2 | q01·근거 8 | 4.654초 | 8.262초 | 성공 |
| smoke 3 | q11·근거 3 | 2.745초 | 5.109초 | 성공 |

세 smoke는 통과했지만 다음 단독 단계의 두 번째 호출에서 실패해 증량을 중단했다. 첫 실행에서는 세부 인용 사유·답변 원문을 보존하지 못했다. 수집을 보강한 **독립 진단 1회**에서 `[[UUID]]` 대신 `[UUID]`로 출력한 사례와 MISSING_CITATION을 확인했다. 첫 실패의 세부 원인도 반드시 같았다고 단정하지 않는다. 실제 모델의 자동 교정/재시도를 추가하지 않았고 정상 성능 표본에서 실패를 숨기지 않았다.

총 6회 사용량은 입력 11,605토큰, 출력 7,119토큰(이 중 reasoning 3,005), cached input 5,760이었다. reasoning을 출력에 다시 더하지 않는다. **캐시 할인 제외 추정 USD 0.04073925**, 두 실행의 미정산 예약은 모두 0이었다. 표본이 작고 계획한 단독 6건/동시 2개 6건을 끝내지 못했으므로 p95·최대 동시 처리량을 선언하지 않는다.

계획한 약 8k 입력 fixture와 프로젝트별 RPM/TPM 상한 기록은 아직 확보하지 못했다. 실제 호출의 입력 usage는 1,503~2,320토큰이었다. 근거 8개를 사용했다고 8k토큰 시험을 완료한 것으로 표시하지 않는다. 다음 증량 전 이를 보완해야 한다.

결과는 Git 제외 `build/answer-generation/live-2026-10-29T07-05-31.742166400Z/`와 `live-2026-10-29T07-08-45.760233600Z/`다. 진단 실행부터 원문은 해당 디렉터리의 별도 txt에 보존하며 Git/공용 로그에 포함하지 않는다. 최초 실행은 원문 미보존 한계가 있다.

재현은 **유료 호출**이다. 기본 전체 JUnit에서는 제외한다.

```powershell
$env:RUN_ANSWER_LIVE='true'
.\gradlew.bat answerGenerationLiveTest
# 단일 진단만 필요하면 ANSWER_LIVE_DIAGNOSTIC=true를 추가한다.
```

최초 진행은 계획의 중단 조건에 도달했다. 이후 위 재실행에서 단독/동시 2개를 확인했지만 간헐적 형식 실패는 남은 위험으로 관리한다. 이후 준비한 C 구성은 [별도 문서](full-rag-preparation.md)를 따르며 실제 호출은 아직 하지 않았다. 기존 내부 Compose/dummy 키는 유지하고 별도 override를 사용한다.
