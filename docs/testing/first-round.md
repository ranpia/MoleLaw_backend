# 1차 테스트

2026-10-28~29에 기록한 시험을 **1차 테스트**로 명명한다. 조회·DB·Redis/Refresh·임베딩·리랭커·혼합 부하·최종 AI 생성·고정 색인 전체 RAG의 기준선이다. 실행별 코드·설정은 원본 보고서를 따르며 단일 커밋에서 모든 시험을 수행한 묶음은 아니다.

리팩토링 이후 회귀 테스트나 후속 성능 측정을 1차 수치에 덮어쓰지 않는다. 다음 성능 측정은 같은 데이터·자원·측정 창·실효 옵션을 맞춰 별도 기록한다. 일반 JUnit 회귀 통과를 성능 개선의 증거로 삼지 않는다.

## 결과와 개선 대상

| 대상 | 1차 결과 | 코드 검토에서 연결할 개선 |
| --- | --- | --- |
| 조회 API | 512 VU 약 146 RPS·p95 17ms, 1,024 VU 지속 확인은 Hikari 대기·HTTP 500 | 방마다 첫 메시지 조회하는 N+1과 사용하지 않는 Page count 제거. 로그인에서 BCrypt·Redis 호출 중 DB 잠금 유지 범위 별도 검토 |
| MySQL | 읽기 연결 증가 시 TPS 개선 없이 지연 증가, 혼합은 32연결까지 증가 | 풀 크기 증액보다 실제 SQL 수·연결 점유 시간 검토 우선 |
| Redis·Refresh | 최종 100세션·120초 약 883.1 RPS·실패 0. 지연·응답 유실 후 이전 토큰 재시도는 family 폐기 | 보안 계약 유지. 무조건 재시도 금지와 장애 복구 경계 보존 |
| 임베딩 | 120초 무거부 질문 동시 5개·문서 동시 2개 | 입력 길이별 관측 유지. 대기열 확대를 처리량 개선으로 가정하지 않음 |
| 리랭커·혼합 | 리랭커 동시 2개부터 거부. 혼합 1+1도 임베딩 대기 만료 | 연산 자원 분리·공정성·입장 제어는 별도 비교 실험 대상 |
| AI 생성 | 최초 인용 실패 후 재실행 16호출 통과 | 인용 검증 유지. 중복 옵션 생성과 실행 시 역할 설정 손실 검토 |
| 전체 RAG | 실제 무저장 1상담 첫 답변 39.002초·완료 42.365초. READ 실효 effort none | 동적 JSON schema와 모델·effort·완료 한도가 함께 보존되는지 회귀 검증 |

수치는 조건별 관측이며 운영 수용량·법률 품질 합격선이 아니다. 그래프와 실패·미실행 범위는 [1차 시각화](visual-results.md), 구체적인 코드 검토·변경·검증은 [1차 개선 및 리팩토링](../plans/first-round-refactoring.md)을 따른다.
