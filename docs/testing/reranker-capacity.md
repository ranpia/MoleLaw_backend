# 리랭커 단독 동시 부하

2026-10-29. KURE 서버의 `/api/rerank`에 직접 요청한다. 임베딩·백엔드 RAG·AI 답변 생성은 함께 실행하지 않는다.

## 입력과 실행 조건

- 실제 법령 4종에서 준비한 전용 Qdrant 1,000개 컬렉션과 저장된 질문 벡터를 사용한다. 8개 질문(법령마다 2개)의 top-20을 한 번 조회하고, 앞의 5개 또는 20개를 고정 입력으로 저장한다. 새 임베딩은 생성하지 않는다.
- 후보 본문·ID·해시를 기존 코퍼스와 대조한다. 고정 BGE 토크나이저로 질문/후보 쌍의 길이를 확인하고, 1,024토큰을 넘는 입력은 허용하지 않는다. 정답 라벨을 가진 검색 품질 평가는 아니다.
- 쌍 길이는 후보 5개 입력에서 57~535토큰(평균 231.5), 후보 20개에서 57~541토큰(평균 198.46)이다. 두 경우의 평균 후보 길이는 같지 않으므로 후보 수만으로 지연 비율을 예측하지 않는다.
- `BAAI/bge-reranker-v2-m3`, revision `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`, CPU 4개·메모리 6GiB·float32·추론 스레드 4개, 내부 predict 배치 2개를 사용한다. 요청당 후보 5/20개와 내부 배치 크기는 다르다.
- 임베딩과 공유하는 추론 잠금은 1개, 대기 슬롯 4개, 대기 한도 5초다. 임베딩 모델은 로드돼 있지만 이번 시험에서는 추론하지 않는다.
- 동시 HTTP worker 1/2/4/5를 탐색하되 처음 거절된 구간에서 증량을 멈춘다. 2개가 성공하고 4개가 거절되면 3개를 추가 확인한다. 별도로 8개 과부하를 측정한다.
- 각 단계는 10초 예열 → 모두 완료 → 별도 60초 측정 → 모두 완료 순서다. 거절이 없는 가장 높은 단계를 120초 확인하고 마지막에 동시 1개로 회복을 확인한다.
- 성공 응답의 모델/revision·후보 개수·ID 순서·중복 여부·유한 점수를 검증한다. 점수는 raw logit이므로 0~1 범위로 제한하지 않는다. 예상한 503(full/timeout)과 전송 오류·잘못된 응답을 구분한다.

현재 설정에서 확인된 무거절 동시 요청은 두 조건 모두 **1개**다. 후보 20개는 요청당 평균 시간이 약 11초여서 CPU 기반 전체 상담 지연에 큰 영향을 줄 수 있다. 다음에는 동일 잠금에 임베딩과 리랭커 요청을 함께 보내 간섭을 확인하고, 후보 수 축소 또는 GPU/모델 변경은 동일 입력 재측정으로 비교한다. 이번에는 서버 설정을 조정하지 않았다.

## 결과를 읽는 방법

성공 RPS는 측정 창 안에 **완료된 성공 수/측정 시간**이다. 지연은 창 안에서 시작한 성공 요청을 drain까지 포함한다. 빠른 503을 성공 지연에 섞지 않는다. 후보 처리량은 `성공 RPS × 후보 수`지만 서로 다른 후보 길이의 계산 비용까지 같다는 의미는 아니다.

입력은 각 단계마다 처음부터 순환한다. 느린 조건은 60/120초에도 8개 질문을 모두 끝내지 못할 수 있다. `validation.json`에 성공한 질문 수와 입력별 횟수를 보존하므로 표본이 작은 p95/p99를 안정적인 운영 백분위로 해석하지 않는다. 과부하에서는 거절 때문에 성공한 입력 구성도 바뀔 수 있다.

지연 SLO를 정하지 않았으므로 120초 무거절은 관측 결과이며 운영 허용 사용자 수가 아니다. 대기 한도 5초보다 단일 추론이 길어지면 동시 요청 2개부터 대기 만료가 발생할 수 있다. 대기 한도만 늘리면 사용자가 기다리는 시간도 늘어나므로, 후보 수·길이·하드웨어·혼합 부하를 함께 검토한다.

## 재현

모델과 관측 환경이 실행 중이고 기존 실제 임베딩/색인 자료가 준비된 상태에서 실행한다.

```powershell
.\scripts\load-testing\run-reranker-capacity.ps1
```

후보 준비 컨테이너는 오프라인 토크나이저 로드 때문에 메모리 1GiB, 부하 발생기는 CPU 1개·메모리 512MiB로 분리한다. 후보 파일이 존재하면 해시와 동일 조건을 검증해 재사용한다. 결과는 Git 제외 경로 `build/rag-dataset/legal-perf-v1/rerank-runs/<실행 ID>/`에 저장한다.

`environment.json`, 단일 요청 검사, 단계별 요약/요청 JSONL, `result.json`, `validation.json`, `server-evidence.json`을 함께 보존한다. 마지막 검증은 요청 창·응답 집계·파일 해시·발생기 자원·모델 준비/메모리·회복과 임베딩 카운터 불변을 확인한다.
