첫 1,000개 코퍼스는 민법 612·주택임대차보호법 45·근로기준법 135·저작권법 208개 청크다.
먼저 질문이 참조하는 조문의 청크를 넣고, 나머지는 법령별 순환 선택으로 채웠다.
이는 실제 서비스의 질문·법령 분포를 추정한 비율은 아니다.

법률 본문에 한정한 사용 근거는 [저작권법 제7조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1029423769)와
[문화체육관광부 안내](https://www.mcst.go.kr/site/s_policy/copyright/knowledge/know04.jsp)를 확인했다.
사이트 UI·검색 결과·관리 부서 연락처·편집 해설은 코퍼스에 넣지 않았다.

Git에 보존하는 기반:

- [조문 스냅샷](../../docker/loadtest/rag-data/snapshot/articles.jsonl): 정규화된 실제 본문과 조문별 출처·해시.
- [수집 이력](../../docker/loadtest/rag-data/snapshot/provenance.json): 다운로드 URL·시각·원본 HTML 해시·제외 조문 수.
- [준비 잠금 파일](../../docker/loadtest/rag-data/snapshot/preparation.lock.json): 토크나이저 파일/라이브러리 버전과 생성 파일 해시.
- [합성 질문](../../docker/loadtest/rag-data/questions.json): 직접 작성한 질문·후보 조문 연결. 외부 상담 기록은 사용하지 않음.

생성물은 Git 제외 `build/rag-dataset/legal-perf-v1/`에 둔다.

| `raw/*.html` | 최초 확보한 HTML, 감사용 로컬 보관. 재생성에는 필요 없음 |

KURE 모니터링 단계에서 준비한 이미지와 테스트 모델 캐시가 있으면 네트워크 없이 재생성한다.

```powershell
.\scripts\load-testing\prepare-rag-data.ps1
```

이 명령은 모델 가중치를 로드하거나 인코딩하지 않고 고정 revision의 **토크나이저만** 사용한다.
캐시는 읽기 전용이며 컨테이너 네트워크도 차단한다. 생성된 내용이 기존 파일이나 잠금 파일과 다르면 중단한다.
스냅샷의 LF 줄바꿈을 `.gitattributes`로 고정해 Windows에서도 파일 해시가 변하지 않게 했다.
최초 수집용 `prepare.py acquire`는 기존 스냅샷을 덮어쓰지 않는다. 신규 수집은 별도 데이터셋 버전으로 관리한다.

## 처리 방식과 한계

- 법령명과 버전 표기를 검사한 뒤 본문 조문의 `joNoList`/`lawcon` 구간만 추출했다.
  삭제 조문과 `sfon` 변경 이력 표기를 제외하고 NFC·공백을 정규화했다.
- 토큰 수는 `nlpai-lab/KURE-v1` revision `8b418a58414668e75532ed045c22d9ca018ae2b2`의 토크나이저로
  **특수 토큰 2개를 포함**해 계산했다. 청크는 원문의 연속 문자 구간이며 실제 길이는 19~512토큰이다.
- 길이별 입력은 여러 조문을 결합한 성능용 자료다. 하나의 실제 조문이나 상담문으로 표시하지 않는다.
  512 구간 1개는 재토큰화 후 511토큰이며 나머지는 목표 길이와 같았다. 실제 길이를 각 행에 기록했다.
- 8,193토큰 자료는 한도 초과 거부 확인용으로, 정상 처리량 시험에 섞지 않는다.
  경계 자료를 실제 모델에 보낸 결과는 아직 확인하지 않았다.
- 질문의 `candidate_articles`는 코퍼스 누락을 막는 후보 연결이다. 전문가 검수된 정답이 아니므로
  이를 그대로 Recall@k 등 검색 품질의 골드 라벨로 사용하지 않는다.
- 현재 실제 고유 청크는 1,504개다. **10,000개 시험을 위해 같은 청크를 복제하지 않는다.**
  고유 10,000개 시험이 필요하면 실제 법령 원문을 추가 확보해 새 버전을 만든다.

검증은 파일/본문 해시·고유 ID/텍스트·원문 문자 구간 일치·1,000개 코퍼스의 참조 관계·질문 후보 포함·
길이 구간·문맥 경계·잠금 파일 일치까지 통과했다. 실제 추론 성능과 검색 품질은 다음 단계에서 확인한다.
