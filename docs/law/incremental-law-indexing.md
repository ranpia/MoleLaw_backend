# 증분 색인과 조문 메타데이터

2026-10-24 사용자 요청으로 추가했다. 새 테이블에는 본문을 넣지 않으며 기존 법령 원문 JSON은 근거 복원용으로 유지한다.

## 관계와 저장 정보

`legal_source.id → legal_source_index.source_id → law_chunk_index.generation → Qdrant point_id`

| law_chunk_index 컬럼 | 목적 |
| --- | --- |
| point_id | Qdrant 포인트 UUID, 기본키 |
| generation | 부모 색인 FK. 상태·모델·원문 UUID를 간접 참조 |
| article_path | 조문번호/가지번호 |
| chunk_index | 조문 내 청크 순번 |
| input_hash | 실제 입력(제목 + 개행 + 청크)의 SHA-256 |

법령 ID·MST·시행일·모델·상태는 부모/원문과 조인한다. 본문·벡터·질문을 새 테이블에 복사하지 않는다.
`(generation, article_path, chunk_index)`는 고유하며 generation에 외래키를 둔다.
V6은 색인 dedup_key, V7은 메타데이터 관계를 추가한다.

## 새 원문 처리

1. 전체 원문 해시·MST·설정이 같고 저장 검증이 성공한 완료 색인은 그대로 재사용한다.
2. 새 원문은 같은 법령 ID/MST와 설정의 완료 색인을 찾아 입력 해시를 비교한다.
3. 이전 Qdrant 포인트의 원문/세대/설정/revision/실제 입력 해시·차원·정규화를 검증한다.
4. 같은 입력의 벡터는 재사용하고 변경/추가 또는 확인된 누락/손상 입력만 다시 임베딩한다.
   통신 장애를 누락으로 간주해 재임베딩하지 않는다.
5. 새 세대의 포인트·메타데이터를 검증하고 마감시간을 확인한 뒤 COMPLETE로 공개한다.

청크 단위이므로 바뀐 조문 안에서도 정확히 같은 입력은 재사용할 수 있다.
제목·조문번호·청킹·모델이 달라지면 같은 입력으로 보지 않는다.
새 원문 수집 시의 처리이며 자동 개정 감시 스케줄러는 별도다.

임베딩 재사용과 Qdrant 쓰기 생략은 구분한다. 세대별 출처·시행 버전과 미완료 비공개를 유지하기 위해
재사용 벡터도 새 세대 포인트/메타데이터로 기록한다. 이전 시행 버전은 보존하므로
버전 간 물리 벡터를 한 개만 보관하는 구현은 아니다. 이전/실패 세대 정리는 별도 보존 정책을 따른다.

## 중복 방지

세대 안에서는 결정적인 ID로 upsert해 같은 배치 재전송에도 포인트 수가 늘지 않는다.
색인은 `MST + 원문 해시 + 설정 fingerprint`의 SHA-256을 nullable unique dedup_key로 예약한다.
같은 WRITING/COMPLETE 작업의 동시 생성은 DB에서 차단하고 BUSY를 반환한다.
실패 시 예약을 해제해 새 세대로 재시도한다. 다른 FK/데이터 제약 오류는 BUSY로 숨기지 않는다.
메타데이터 보강은 부모 행 잠금으로 직렬화한다. 장애로 남은 WRITING 회수/lease는 P05에 남아 있다.

## 기존 포인트 연결

스크립트는 읽기 전용이 기본이다. COMPLETE와 payload·개수·결정적인 포인트 ID를 대조한 뒤
`--apply`에서 ID/해시와 완료 색인의 중복 방지 키만 보강한다. 본문·벡터를 쓰거나 삭제하지 않는다.
기본 안전 상한은 10,000포인트다.

```powershell
python scripts/backfill-law-chunk-index.py
python scripts/backfill-law-chunk-index.py --apply
```

현재 COMPLETE 3개/495포인트는 기대 개수와 모두 일치하며 동일 원문·설정의 완료 중복과
COMPLETE 밖 포인트가 각각 0이었다. 메타데이터 495행과 완료 색인 예약 3개를 등록했다.
회귀는 반복 upsert, DB 고유/FK 제약, 조문 2개 중 1개 변경 시 임베딩 1개,
입력/세대가 다른 벡터의 재사용 거부를 검증한다.
