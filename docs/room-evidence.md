# 상담방 최초 근거와 인용 검증

## 저장과 사용

`LegalEvidenceCollector.collect`가 실제 사용할 법령 청크와 판례 목록 메타데이터를 `EvidenceItem`으로 복사하고 `LegalAnswerService.prepareInitialAnswer`가 최초 답변을 생성합니다. 각 항목은 서버가 만든 UUID, 종류, 원본 식별자, 제목, 출처 URL, 사용한 본문을 갖습니다. 법령 청크는 전체 법령 원문을 의미하지 않으며 `CASE_METADATA`는 판시사항·판결 이유의 근거가 아닙니다.

모델이 이 ID로 인용한 답변을 생성하면 서버가 검증합니다. `ChatTurnService.saveInitialTurn`은 모델 호출이 끝난 후 방·근거·암호화된 USER/BOT만 한 트랜잭션으로 저장합니다. INFO는 저장하지 않고 조회 시 스냅샷에서 렌더링해 최초 BOT 다음에 삽입합니다. 실패하면 방도 남기지 않습니다. 후속 USER/BOT도 같은 서비스의 별도 공개 트랜잭션에서 함께 저장합니다. 근거가 없으면 최초 답변을 생성하지 않습니다. [저장·암호화·한도와 조회 계약](chat-storage.md)을 따릅니다.

`chat_evidence_snapshot`은 `room_id` 기본 키로 방당 한 행만 보관합니다. 최초 근거 JSON·SHA-256·저장 시각을 고정하고 덮어쓰지 않습니다. 최대 100항목·UTF-8 JSON 2MiB이며 방을 삭제하면 함께 삭제합니다. 업무 DB의 기존 법령 청크나 벡터 색인이 바뀌어도 이 사본은 바뀌지 않습니다. Flyway V2로 테이블을 생성합니다.

## 후속 상담

`ChatEvidenceService.load(userId, roomId)`가 소유권·스냅샷 해시·필드를 확인한 뒤 고정 ID·종류·제목·본문을 답변 Client에 제공합니다. `MessageChatMemoryAdvisor`는 별도로 대화 기록만 복원합니다. 대화 속 이전 인용이나 INFO를 원문 근거로 재해석하지 않습니다. 추가 검색·수집은 수행하지 않습니다.

스냅샷이 없는 기존 방은 실패 처리합니다(`GPT_API_FAILURE`). 이전 대화만으로 근거를 추정해 자동 보충하지 않습니다. 새 상담방에서 다시 시작해야 하며 별도 이관 기능은 제공하지 않습니다.

## 인용 계약

- 모델은 `[[xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx]]` 형식의 소문자 UUID로 인용합니다.
- `CitationValidator`는 최초·후속 답변 모두에서 허용된 ID 소속, 형식, 인용 누락을 검사합니다. 다른 방 ID·새로 만든 ID·잘못된 마커는 거절합니다.
- 모델이 작성한 HTTP(S) URL도 거절합니다. 출처 링크와 ID 안내는 최초 INFO에서 서버가 생성합니다. 반환 JSON 필드는 유지하며 답변 본문에 인용 ID가 포함됩니다.
- 검증 실패 답변은 저장하지 않고 오류로 종료합니다. 자동 수정·재생성은 하지 않습니다.

검증 범위는 **고정 근거의 식별과 인용 계약**입니다. 문장의 법적 결론이 인용 본문에서 도출되는지, 모든 주장에 적절한 인용이 있는지, 최신·시행 법령인지까지 판정하지 않습니다. 의미 검증과 근거 충분성 평가·수집 반복은 후속 과제입니다. 스냅샷 전체 입력과 대화 기록에 대한 토큰 예산도 별도로 관리해야 합니다.

## 검증

`.\gradlew.bat test`는 최초 근거 복사·인용 허용/거절·소유권·해시·Advisor 주입과 H2의 실제 저장·삭제·트랜잭션을 검증합니다. `.\gradlew.bat mysqlIntegrationTest`는 격리 MySQL에서 V1→V2와 JPA 매핑을 검증합니다. 모델 API는 모킹하며 실제 법률 답변 품질 검증은 별도입니다.
